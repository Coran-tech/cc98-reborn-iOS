# 原生 UI、本机增强与长时登录真机验证

目标设备：**iPhone 16 Pro / iOS 26.5.2**，App 最低支持 iOS 17。本轮验证分支为 `codex/ios-mobile-ui`，以原生五栏界面为准。

当前 UI 候选版本为 **0.4.0**，以已构建的 0.3.0 / Build 82 长时登录版为基线。候选构建编号与云端结果见 [README](README.md)。模拟器使用合成离线数据，不能代替下表真实服务与真机状态。

## 安装与准备

1. 从本分支成功的 GitHub Actions 下载 artifact，确认 `build-status.txt` 没有失败项，取出 `CC98RebornShell-unsigned-device.ipa`。
2. 沿用已成功使用的 Windows 自签工具。保持原签名身份和 App 标识，优先覆盖安装；不要先卸载含有草稿的版本。Apple Account 与双重认证由你自行输入。
3. 按系统要求启用开发者模式。自签有效期、重签后 Keychain 访问权限与论坛授权期限分别检查。
4. 连接校网或系统 VPN。论坛 API 与 OpenID 系统窗口都应可达；仅浏览器能够打开 CC98，不足以证明 App 的网络路径可用。
5. 准备一条不敏感草稿、一张不敏感测试图片。涉及发帖、私信或投票时，只在获准的测试位置操作，不向无关用户发送内容。

不要发送真实 token、密码、验证码、Cookie、Authorization 请求头或完整 OAuth 回调。也不要修改令牌或设备时间来缩短测试。

## 第二阶段：正常续期与多账号

后台页面显示访问令牌 1 小时。以实际签发期限为准，正常使用至少跨过 **两个访问令牌有效期**；按该页面值安排测试时，应留出超过 2 小时的观察窗口。期间可锁屏、退出重开和切换网络，不要求 App 一直前台运行。

| 项目 | 操作 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| 首次自动续期 | 登录后正常阅读，在首个有效期之后读取收藏、消息等需登录内容 | 无需重新输入密码或同意授权；内容仍属于原账号 | 待真机 |
| 轮换后的再次续期 | 继续跨过第二个有效期，再次读取需登录内容 | 第二次仍正常，证明不是仅首次刷新可用；无反复登录循环 | 待真机 |
| 到期前后并发读取 | 在观察窗口内快速打开首页、消息、我的等页面 | 不出现部分页面突然要求登录、账号错乱或连续刷新失败；请求合并由云端行为测试补证 | 待真机 |
| 到期时离线 | 有效期后暂时断网，打开需登录页面，再恢复校网／VPN重试 | 离线期间不删账号；恢复后能续期，不需要为网络错误重登 | 待真机 |
| 多账号隔离 | 如有第二个获准账号，添加后在 A、B 之间切换并读取各自收藏、消息 | 当前头像、账号标记、实际内容一致；各账号本机内容不互串 | 待真机／无第二账号则未测 |
| 切换失败恢复 | 切换时断网或使用暂不可用账号，再恢复网络 | 明确未完成切换；仍使用原身份，不把旧响应显示为新账号资料 | 待真机／需第二账号 |
| 切换中的读取 | 发起读取后立即切换账号，观察请求完成后的页面 | 旧账号结果不覆盖新账号状态；必要时提示重新操作 | 待真机／需第二账号 |
| 授权失效后的恢复 | 仅在自然失效或已安排的受控撤销授权后，使用当前账号按钮或该账号菜单中的“重新授权” | 对应账号需要重新授权，账号和草稿保留；不自动借用另一账号执行操作 | 待条件满足 |

受控撤销现有客户端授权可能同时影响桌面扩展或其他使用同一客户端的会话；不为本轮测试贸然撤销。并发时序、明确 `invalid_grant`、存储失败等场景先由合成测试覆盖，真实站方失效行为单独记录。

两个小时的正常续期测试不能证明 15 天／30 天边界或客户端未审核限制已经解除。后续按自然经过的时间记录长期结果，不用短测推断永久有效。
