# CC98 Reborn 原生 iOS 手机端 UI 设计规范

- 文档版本：2.2
- 修订日期：2026 年 10 月 22 日
- 实现基线：DeepSeek 原生分支 deepseek/ios-verification-shell，提交 696be96
- 适用平台：iOS 17 及以上，优先适配 iPhone；当前验证设备为 iPhone 16 Pro
- 用途：后续 UI 整理、交互完善、页面设计与功能验收

以现有原生客户端为基础，保留五栏导航、直接调用 CC98 API 的业务路径、多账号登录、新帖双视图、原生编辑器与本机内容管理。设计工作的重点是改善信息层级、阅读宽度、工具密度和状态反馈，而不是重新套回网页壳，也不是为了统一外观删去已实现的功能。

登录体验以“正常使用时长期免重复登录”为目标：访问令牌正常到期后自动续期，而不是每次要求重新授权；断网、离开校网和 App 重启不主动清除账号。长期会话必须建立在站方允许的刷新授权之上，具体期限与条件见第 17 节。

本版替代 1.0 中以网页壳为基础的架构、四入口、网页登录后另行绑定、仅保存身份摘要及原站模式常驻等设计。未被架构变化影响的可读性、权限、草稿与隐私原则继续保留。

“必须”是后续验收要求，“应”是默认设计方式，“可”是满足条件后的扩展。文中的“已有”表示存在对应原生代码与调用路径；“待完善”表示已有功能需要补齐指定状态或调整交互；“待接入”表示尚未在当前原生主路径形成完整能力。三者都不代替真机验收。2026 年 10 月 22 日起按用户确认进入实现阶段，先完成第 17 节长期登录，再推进界面整理；本轮不全面改版 UI。

## 1 实现基线与功能保留原则

### 1.1 当前主路径

当前 App 入口是 NativeRootView。页面采用 SwiftUI；CC98API 直接请求 https://api.cc98.org；NativeAuth 使用 CC98 OpenID 系统授权窗口并取得原生业务会话；NativeTokenStore 按账号把令牌存入 Keychain；NativeLibrary 按账号管理本机内容。

UBB 和 Markdown 由原生渲染器解释。帖子、回复、私信、资料修改、投票、评分和上传不再普遍依赖原站网页控件执行，必须分别处理服务端结果和权限。原站依然是业务规则与访问权限的最终依据。

旧 ShellView、ShellModel、网页注入资源与旧授权代码仍在仓库中，但当前 App 入口不经过旧网页壳。不能仅因旧代码存在，就在界面上宣称原站模式、网页同账号绑定或完整插件设置已经可用。

### 1.2 本轮保留的产品结构

以下内容作为现有功能基线，不因整理 UI 被移除：

- 首页、版面、新帖、消息、我的五个主入口。
- 新帖“全部／图文”筛选、列表／双列卡片切换及缩略图。
- 版面分类、搜索、大字报、版内搜索、发主题和发投票。
- 读帖分页、楼层跳转、上拉下一页、可选浏览进度、热评、评分、签名、投票和站内链接。
- 图片查看、原生 UBB／Markdown、正文大表情与表情选择器。
- 主题、回复、引用回复、编辑、图片和附件上传、投票设置、草稿操作与 @ 提醒。
- 回复、@我、系统、私信四类消息，以及私信收发。
- 收藏分组、关注与粉丝、个人主页、资料和头像编辑。
- 稍后再看、本机历史、主题备注、主题及内容屏蔽。
- 多账号添加、切换、退出当前账号，以及前台消息检查和本地通知。
- 浅色、深色、跟随系统与现有浅深 App 图标资源。

### 1.3 功能不能被视觉整理偷偷改变

- 隐藏按钮、换位置、收进菜单，不等于可以改变它的数据含义。
- 主题备注不是用户备注，稍后再看不是原站收藏，本机浏览历史不是原站足迹。
- 原生登录不是浏览器 Cookie 登录；退出本机账号不是撤销站方授权。
- 当前正文编辑是源码输入加预览，不把它描述成已经具备完整所见即所得双向编辑。
- 新帖卡片模式是保留项，不能因新版偏好简洁而直接删去；列表仍是默认模式。
- 不把实现缺陷固定成规范。影响身份、数字口径、草稿或权限的差异在第 24 节明确记录，后续修复后再验收。
- 桌面版尚未迁入的功能列入待接入清单，不在原生界面放可点击的假入口，也不宣称已完整复刻桌面版。

## 2 设计目标与能力分层

### 2.1 优先顺序

**身份与业务正确 → 输入不丢与操作可恢复 → 阅读和触控清楚 → 页面连贯 → 信息密度 → 装饰。**

核心任务依次为找主题、读帖定位、回复编辑、处理消息、整理个人内容和恢复异常。不能为了首屏多放两条内容，把操作文字压成 10 号，或把整篇正文截断。

### 2.2 视觉方向

延续 ShellTheme 的青竹与深灰体系，保留原生导航、系统选择器和表单的熟悉感。内容面平静、文字有层级，按钮与状态容易辨认。

- 不新增宣传型首页、大幅问候卡、与阅读无关的数据看板。
- 当前首页已有今日帖子、在线、主题统计，保留为十大之后的次要信息，不把它升级成首屏主角。
- 普通列表按内容分组，不让每行都变成厚阴影卡片；新帖卡片模式可以使用真实卡片。
- 帖子维持单列楼层阅读，不恢复桌面作者左栏和右侧工具栏。
- 系统材质只用于控制层，正文、引用、表单和错误说明有稳定背景；兼容 iOS 17，不以仿制新系统毛玻璃为实现前提。
- 不随机为每个版面、作者和统计数字着色，不用渐变、发光和持续动画承担信息层级。

### 2.3 使用与权限边界

必须在校网或覆盖所需请求的系统 VPN 环境下使用。App 不提供公网代理，不能仅凭请求失败断言 VPN 已断开。

已公开可读的内容不为强制登录而额外拦截；需要身份的操作使用登录引导。匿名、删除、回复可见、投票后可见和受限版面的真实规则不能被重排、缓存、缩略图或搜索绕过。

本机内容不意味着整篇帖子已离线保存。前台消息检查不意味着后台推送。拥有 refresh token 时才有相应续期路径，不能承诺永久登录。

### 2.4 当前原生能力分层

| 分类 | 典型内容 | 后续设计原则 |
| --- | --- | --- |
| 已有原生实现 | 五栏、API 读写、登录、多账号、帖子、消息、收藏、上传 | 保留调用目标与功能入口，改进排版和反馈 |
| 已有但待完善 | 草稿保存反馈、清空确认、账号恢复、复杂屏蔽、分页密度、批量读取 | 单列缺口，完整画出恢复与失败状态 |
| 桌面版有但原生待接入 | 收藏夹分享、配置备份、用户备注、完整高级规则、BBS、六组配色 | 不写成已有，保留功能规划与数据约束 |
| 特殊依赖尚未接入 | 问号服务、AI、本地语义服务、远程推送 | 独立范围和授权，核心界面不放假开关 |

## 3 五栏导航与页面容器

### 3.1 主导航固定为五栏

顺序保持：**首页、版面、新帖、消息、我的**。搜索和发帖是当前页面动作，不增加第六栏，不把新帖重新并入首页。

| 入口 | 核心内容 | 顶部常用动作 | 返回时保留 |
| --- | --- | --- | --- |
| 首页 | 今日十大、现有论坛统计 | 搜索 | 列表锚点和已读上下文 |
| 版面 | 分区、版面、目录搜索 | 版面搜索 | 分类、搜索词、当前版面和列表位置 |
| 新帖 | 全部／图文、列表／卡片 | 视图切换、发帖 | 筛选、布局、已加载范围和阅读位置 |
| 消息 | 回复、@我、系统、私信 | 当前分类的管理操作 | 分类、联系人、会话和未发送输入 |
| 我的 | 账号、个人内容、设置 | 账号管理或必要的更多 | 当前账号及子页位置 |

每栏使用清楚的图标与文字，选中态同时体现在图标／标记与颜色上。主入口不因未登录、无内容或网络错误消失或换位。五栏在小屏或大字下按系统适配，不能把第五栏挤成不可发现的“更多”。标签栏用于导航，不用作发布或刷新按钮。[Apple 标签栏指南](https://developer.apple.com/design/human-interface-guidelines/tab-bars)

### 3.2 使用现有原生导航栈

- 根页面和普通浏览子页使用 NavigationStack 的层级导航，不为了符合旧规范把所有页面改成模态全屏。
- 读帖保留进入详情后隐藏根标签栏的现有方向，顶部有明确返回；底部只呈现读帖工具，不再叠根导航。
- 私信会话和持续输入任务进入专注布局，键盘出现时不同时堆根导航与多排无关控件。
- 发帖、回复、编辑、投票编辑和涉及未保存输入的资料修改，采用足够大的任务容器；不能把长表单锁在半屏。
- 排序、选择分组、楼层输入、短操作菜单使用底部面板；长期阅读的对话和全文搜索可扩大到全屏。
- 同类内容逐层导航，避免连续覆盖多张 sheet。只读面板可手势关闭；有未提交输入先做退出保护。

### 3.3 每个控制只出现一次

适配页面不得同时显示旧壳标题、原站桌面顶栏和原生导航栏。一个页面只使用一套来源、标题、账号和加载状态。

读帖允许“分页行 + 操作行”作为同一底部控制组，这是对当前大分页按钮的保留；不同时再出现根标签栏、第二套悬浮分页或网页工具条。编辑允许保留双行格式工具，但不额外叠加相同的一套键盘工具。

### 3.4 返回、站内链接和外部网页

- 同帖页码与楼层定位在当前主题中处理，跨主题、版面、用户链接进入对应原生页面。
- 返回上一级恢复来源锚点、筛选与已加载内容，不重新回首页。
- 我的回复、搜索命中和通知中的楼层链接，必须按相同的楼层／页码映射定位，不能只打开主题第一页。
- 外部链接使用系统网页能力，保留真实来源；不附带原生 Bearer，不伪装成已适配的原生页面。
- 当前没有从 NativeRootView 接入完整旧壳恢复流程。兼容操作命名为“在网页中打开原帖／版面”，不写成已可用的“切回原站模式”。
- 网页 Cookie 与原生令牌独立，网页可能需要另行登录。不能为了免登录把原生令牌写进 URL、脚本或剪贴板。
- 用户主动请求兼容打开时，先保护未提交输入，再交给相应容器；不因内容难渲染静默跳出 App。

### 3.5 账号变化时清除旧页面上下文

切换账号后重新取得私有列表、收藏状态和权限。旧请求返回不能覆盖新账号页面；现存帖子详情不能沿用旧账号的赞踩、编辑按钮与私有内容。

有输入或写操作进行中时，先要求完成或处理当前任务，再允许换号。只取消本地等待不代表服务器撤回已发送操作。

## 4 尺寸与响应式布局

### 4.1 设计尺寸与适配范围

主稿为 402 逻辑点宽，必须同时检查 320、375、393、430，以及横屏和系统大字。系统安全区、灵动岛、键盘与 Home 指示条以实际环境为准，不写死机型截图像素。

原生使用逻辑点及动态文字。旧网页兼容页有独立视口，不把原生 pt 机械当成 CSS pt。界面要适应尺寸、安全区、方向与文字变化。[Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)

### 4.2 布局尺度

| 项目 | 默认规范 |
| --- | --- |
| 页面水平边距 | 16；320 宽时可降至 12 |
| 内容组内间距 | 4、8、12、16 |
| 内容组间距 | 20、24；长表单可用 32 |
| 独立按钮触控范围 | 最小 44 × 44 |
| 主操作按钮 | 最小高度 48，随文字增长 |
| 常规表单与设置行 | 最小 52，多行自然增长 |
| 图标视觉尺寸 | 20–24，不等同于触控范围 |
| 列表头像 | 32–40；资料头像 56–64 |
| 通用圆角 | 内容组 12，输入及小面板 8 |
| 分隔线 | 细线按屏幕比例呈现，不作唯一交互边界 |
| 单列正文最大宽度 | 约 680，宽屏居中，不拉成超长行 |

相邻独立按钮应有约 8 间隔或使用清楚的系统分组。正文内链接按文本流排版，不强行撑出 44 高的空白，但不得密集重叠。

### 4.3 避免双重内边距

402 宽、两侧各 16 时主要正文宽为 370。常规读帖不再叠一层外卡片和另一层 14–16 内边距，把正文压到约 340 或更窄。

保留楼层组的视觉边界，但优先使用全宽内容面、轻分隔与段间留白。若某个独立投票或提示需要卡片，只有该组件保留合理内边距。

### 4.4 小屏、横屏与双列卡片

- 读帖、编辑和普通列表在手机保持单列。
- 新帖双列卡片是明确例外。左右边距 16、列间距 12 时，402 宽每列约 179；320 宽即使减边距也很窄，优先降为单列卡片。
- 大字或可用列宽不足以读清标题时，卡片临时单列；保留用户原来的卡片偏好，不重置成列表。
- 宽度 600–839 仍以舒服的单列为主；更宽双栏属于后续扩展，不是首轮 iPhone 验收前提。
- 横屏不能强制变桌面网页；键盘和阅读任务按可用高度重排。
- 整页不得横向滚动。代码、宽表格和特殊公式可在局部区域横向滚动，不能撑破正文宽度。

### 4.5 安全区和键盘的单一处理

屏幕由一个布局所有者处理底部安全区与键盘避让；子组件不能重复加同一份高度。固定工具组为正文预留实际占位，最后一段、最后一个上传项和最后一条私信必须可见。

## 5 文字与中文排版

### 5.1 字体层级

沿用系统字体和 ShellTheme 的动态文字方向，中文使用系统回退。代码使用系统等宽，不依赖外部字体下载。

| 用途 | 默认字号 | 目标行高 | 使用方式 |
| --- | --- | --- | --- |
| 根页面大标题 | 系统大标题，约 28–34 | 随系统 | 仅根页，进入详情转紧凑 |
| 紧凑导航标题 | 17 | 22 | 半粗体，使用短标题 |
| 主题完整标题 | 22 | 31 | 半粗体，自然展开 |
| 列表标题 | 17 | 25 | 中等／半粗体，默认 2–3 行 |
| 楼层、私信、主要输入 | 17 | 约 27–28 | 正文不截断 |
| 辅助说明、日期与版面 | 13 | 19 | 可读次要色，必要时换行 |
| 短标签与非关键计数 | 12 | 16 | 不承载权限或错误解释 |
| 源码与代码 | 14–15 | 21–23 | 等宽，局部横向滚动 |

这是设计基准，不是当前所有页面已经采用的测量值。现有消息分类、评分记录、分页说明和操作条中的 10–11 号文字应通过重排改善，不能把小字号当作保留功能的唯一办法。

### 5.2 正文

中文左对齐，不默认两端对齐、首行缩进或额外字距。段落间保留约半行至一行间距。保留作者有意义的换行、列表、代码与原样文本。

长链接、文件名和英文能够折行；不能为了一个字符串撑宽整页。正文不设行数截断；签名、引用摘要、列表预览可以明确折叠，并有完整查看入口。

作者指定字号、色彩和对齐尽量保真；遇到不可读颜色或溢出时进行可读性适配，但不能改变文字含义、隐藏限制或提交源码。

### 5.3 大字与辅助文字

界面响应系统动态文字；后续正文大小设置属于新增阅读偏好，未接入前不展示假滑块。系统放大与应用偏好只合成一次有效尺寸，避免双重放大。

200% 文字放大时，按钮、表单和元信息允许多行；小屏允许分页工具变为上下布局，不缩字。320 宽下主要文字单列重排，局部二维内容除外。[Apple 无障碍指南](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[WCAG 重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 5.4 用户、楼层、数字和时间

- 原用户名始终可识别，匿名只展示原站公开身份，不从 API 的其他字段推导并显示真实用户。
- 楼层使用“1 楼”“128 楼”；楼层链接、通知与回复保持同一映射。
- 普通列表可显示“1.2 万”等紧凑数字；投票、评分变动和其他关键数据保留精确数值或明确详情。
- 缺失数字显示“—”或尚未取得，不当作零；没有完整评分时不显示伪造的最终合计。
- 相对时间应有完整日期的查看方式，历史信息包含年份；不截掉时区后把服务器时间当本地时间。
- 长用户名、版面名、标签和评分理由可换行；不挤掉关闭、提交等关键控件。

### 6.2 颜色用途

主色用于主要动作、当前选择与焦点；副色用于链接及辅助跳转。红、绿保留原评分含义，数值和符号不能只靠颜色区分。正文链接有可发现的文本样式，不将整段正文染成链接色。

深色浅绿按钮需要深色可读前景，不继续硬套白字。错误有文字和图标；锁定有锁图标与说明，不在整页铺警戒纹。

### 6.3 当前外观设置保留原生含义

原生现状为**跟随系统、浅色、深色**，首次默认跟随系统，保留用户已保存选择。不能迁回旧网页的“07:00／19:00 自动切换”，也不把这两种“自动”混为一谈。

六组配色、自定义色、圆角选择与 ASCII／BBS 仍属于待接入功能。后续保留规划，但不能在本次原生设置中宣称已有，也不能为了实现新风格删除现有阅读和编辑能力。

已有浅深 App 图标资源应保留。其显示由实际系统和安装配置决定；没有现成能力时，不设计“已支持任意切换图标”的假按钮。

### 6.4 水印层

保留当前账号 watermarkId 前八位形成的原生水印，切换账号后及时更新，退出后不继续显示旧账号身份。水印不能拦截点击、阻止选区、污染 VoiceOver，或成为重复朗读内容。

缺失或无效时不生成假水印，不复用上一账号。账号状态提供资料重试和可辨识异常；不能把原生问题包装成已完成旧网页绑定。水印不提供任意编辑和关闭开关。

## 7 通用组件与交互

### 7.1 列表行与卡片的边界

版面、消息、收藏、关注和设置以列表为主。新帖卡片、投票和独立内容组可以使用卡片；读帖避免楼层外层重复包卡。

主题列表优先展示标题、版面、回复数与最近时间，再安排作者与浏览数。正常行随标题增高，不固定高度挤字。锁定、投票、置顶等只显示真实状态；重要标记不能藏在不可读的小色点中。

整行打开主题，作者、版面和更多的点击区彼此明确。列表滑动和长按可作为快捷方式，但收藏分组、屏蔽与删除等必要操作另有显式菜单。

### 7.2 按钮与工具

每个局部任务只有一个主要提交动作。图标统一使用系统符号或统一图标体系；同一操作保持相同名称。仅图标按钮必须有无障碍名称与执行状态。

布局不足时合并低频动作到更多菜单或分行，不减小触控。加载中保持按钮位置和宽度，避免后一个按钮跳到手指下。

### 7.3 表单

字段使用常驻标签，单位、必填和限制贴近字段。占位文字不代替标签，错误不只在页面顶端闪一下。

输入值与错误保留，首个错误可被定位；不因资料或选项异步补齐重置正在输入的值。权限判断中的“尚未取得”与“确实不允许”分开。

### 7.4 面板与确认

只读选择可轻扫关闭；未保存输入需要明确保护。批量清空、丢弃草稿、移除账号和涉及费用的匿名操作说明对象与影响。

按钮使用“移除账号”“保存草稿并退出”“丢弃修改”“清空本账号历史”等具体动作，不用“继续”代替风险选择。普通收藏与查看不反复确认。

### 7.5 异步反馈

点击后立即有反馈，后台结果决定最终成功。可测量才显示百分比；不能测量时显示阶段或活动状态，不编造上传进度。

读取可取消；已发送的发帖、投票、私信或删除，不把“停止等待”说成服务器已撤回。失败保留已有内容，结果不确定时先核对，不自动重复提交。

### 7.6 搜索页面

保留当前原生“全站／版内／用户”三个搜索范围；版面目录的名称搜索仍位于版面页，不把两种搜索混称为同一接口。

- 从首页进入默认全站，从版面进入预选当前版面；范围和目标版面必须可见。
- 输入框有明确标签、清除、搜索按钮与键盘搜索动作。更换范围可保留关键词，但清除不再适用的结果与分页，不把旧范围结果当新结果。
- 结果列表保留主题、作者或用户资料、时间及当前可用信息；用户命中进入原生用户页，主题命中进入原生读帖。
- 搜索中、尚未开始、无结果、下一批失败分别呈现；无结果不清关键词，继续加载失败不清已有结果。
- 修改关键词或目标版面后，旧请求不能覆盖新结果；返回结果页保留查询和定位。
- 搜索历史、额外排序、AI 联想尚不是当前完整原生能力，未接通前不画成已有控件；搜索词不发送给外部 AI。

## 8 首页与十大

### 8.1 首屏顺序

紧凑或系统大标题、搜索入口 → 今日十大 → 现有论坛统计。论坛统计保留今日帖子、在线、主题，视觉权重低于主题列表。

不将首页改成“全部／新帖／关注／精选”的四分类总入口，以免与独立新帖栏重复。关注主题流、精选等旧插件内容待接入后另定入口，不混称现有首页功能。

### 8.2 十大行

排名、标题、版面、必要作者与回复信息应清楚。正常可用内容完整显示；超长标题可到详情看完整文字，不以缩字维持统一行高。

保留稍后再看、屏蔽此帖及已支持的作者屏蔽动作。过滤后不能重新编号伪装成原站排名；应保留真实名次，并说明有条目按本机规则隐藏。

### 8.3 状态

十大取得失败不显示“暂时没有十大”，统计失败也不应抹掉已有主题。分别支持初次加载、空内容、局部失败、下拉刷新和重试。

若主数据与后备来源的含义不同，使用准确标题，不把周热榜无提示地称为“今日十大”。这属于数据口径要求，不由 UI 标题掩盖。

## 9 版面与版内浏览

版面目录保留分区、版面名称、说明、锁定状态、现有统计与搜索。分区标题有清楚层级，长名称正常换行；不把大量版面塞进图标九宫格。

版面详情保留本版大字报、主题列表、版内搜索、发主题和发投票。大字报可展开收起，默认遵循已有展开方向；重要发帖条件不可只藏进更多菜单。

- 搜索到版面后保留搜索词与目录上下文。
- 版内搜索预选当前版面，不静默退回全站。
- 发主题默认使用当前版面；从新帖发帖时再选择版面。
- 投票入口受 canVote 等真实能力约束；主题类型和匿名规则显示对应条件。
- 顶部常用动作保留搜索、发主题；发投票可归入发布菜单，功能不能消失。
- 原生目录当前没有完整的本地版面置顶体系；待接入前不渲染无数据的“我的置顶”模块。

## 10 新帖列表与双列卡片

### 10.1 保留两套视图

顶部保留全部／图文筛选，右侧保留列表／卡片切换和发帖。默认列表；已有卡片偏好优先，不在升级时清掉。

切换视图不重新读取同一批数据，不改变筛选，不把用户送回列表首条。用主题 ID 与相对位置恢复，而不是复用不适合另一布局的裸滚动像素。

### 10.2 列表模式

标题 17、最多约 3 行，版面与时间 13。缩略图可作为辅助，标题和必要统计不依赖缩略图加载成功。无图片时采用普通主题行，不用整块空白或装饰封面占位。

条目动作保留加入稍后再看、屏蔽主题和作者。以显式更多菜单补充现有滑动动作，长按不能是唯一发现路径。

### 10.3 卡片模式

- 保留双列与有图／无图两类真实卡片，不要求每帖都有封面。
- 标题默认 16–17、最多约 4 行；摘要最多 2 行，不能从无权限或隐藏内容提取。
- 元信息不低于 12，必要版面信息优先使用 13；空间不够先减少次要统计，不压到 10。
- 图片是预览，不应为了统一高度裁掉具有关键文字的全部内容；点卡片仍打开帖子，原图到帖子查看。
- 当前 112 高预览可作为参考，不锁死所有设备比例。卡片异步得到缩略图时尽量保持占位，避免整列跳动。
- 小屏与大字可变单列卡片，保留同一套信息和用户偏好。
- 保持接口时间顺序，不额外按封面、热度或卡片高度重排数据；VoiceOver 的阅读顺序按原列表，而非先读完整左列再读右列。

### 10.4 缩略图与加载

已有按条目解析图片和必要时读取首帖的逻辑，保留功能，但不得扩大成预读整帖。缩略图不得泄露隐藏图片或受限内容；失败不影响主题可打开。

保留自动加载与“点击继续加载”。失败时明确说明加载失败并提供继续动作，不只显示同一按钮掩盖原因。当前客户端新帖读取范围上限为 500 条，结束文案应说明达到本次可读取范围，不写“全站已无更多帖子”。

## 11 帖子阅读与分页

### 11.1 页面结构

从上到下：原生返回与短标题 → 版面与完整主题标题 → 状态及必要元信息 → 首帖 → 投票 → 热评 → 普通回复 → 底部控制组。

首帖、投票、热评只按当前分支相应页面逻辑出现，不把后续页重复插入首帖和整组热评。热评预览与正文楼层有明确标记，不能因去重导致原楼层定位失效。

锁定、删除、匿名以及特殊可见／发言限制以接口定义与服务端实际规则为准。不能仅凭字段名字推断“非楼主不可阅读”，也不能把特殊权限含义泛化成所有用户都被客户端禁止查看。

### 11.2 楼层排版

作者区包含头像、原用户名／匿名标识、楼主或精彩标记、时间与楼层号。头像视觉约 32–36，点击范围至少 44；匿名不通过头像或作者跳转暴露身份。

正文使用连续可读内容面；评分、签名和操作区依次分组。主题全局边距已经留出 16 时，不再额外压缩每楼正文行宽。

签名档保留，但长签名可折叠预览，匿名发言不显示实名签名。折叠签名与筛选正文、搜索全文之间的语义不能混乱。

### 11.3 楼层动作重新分层而不删功能

保留赞、踩、引用、查看对话、风评及有权限时的编辑。

默认操作区显示赞、踩、引用、更多；查看对话、风评、编辑、复制楼层链接由更多进入。用户不需要把一排 11 号小字横扫一遍才能操作。可通过合适的宽度分行，但不能每楼固定多排工具挤压正文。

赞踩的当前选择、取消、数量与执行中状态清楚，缺数据不当作零。风评与赞踩是不同业务，不互相替代。编辑只按真实权限出现，不能只因展示用户名相同就放行。

### 11.4 评分记录

保留楼层内评分记录与风评合计，提供完整记录视图。默认展示必要记录；过多时可收起并显示实际条数，但不丢数据。

操作人、操作、理由至少有可读字号。小屏把三列表格变成纵向记录或宽裕的两行条目，不使用 10–11 号压缩。财富等非风评记录可保留显示，但不得加进风评合计。

未读全记录时标注当前统计范围，不能把部分合计称为最终值。筛选条件与记录表的风评口径须一致，见第 24 节。

### 11.5 分页与上拉下一页

当前每页按 10 楼映射，保留明确页码和上一页／下一页。楼层跳转输入支持首帖、指定楼层和末页。

保留大分页按钮和上拉下一页，但控制占位应有限：

- 默认将分页行和回复／收藏／更多行合成一个底部控制组；不另叠主标签栏。
- 分页行使用可读文字、至少 44 高的触控，不强制每个按钮 104 宽导致 320 屏溢出。
- 普通字号整个控制组目标约 96–112 高，不含安全区；大字可增加高度或把低频动作收进菜单，不能遮正文。
- 上拉只在已经到底、存在下一页并超过明确阈值时触发；正常回弹、图片拖动与下拉刷新不触发。
- 始终保留显式下一页，不要求用户会手势。
- 换页开始后不接受第二次触发；数据就绪再一次定位，失败仍能回当前页。
- 不能为追求“连续感”无提示改变当前帖子分页与楼层链接含义。

### 11.6 浏览进度

保留“保存浏览进度”开关，默认关闭。关闭时通常从首帖进入，但外部明确页码／楼层链接仍优先。

开启后保存当前账号的主题进度。当前实现主要记录页及页首楼层，不应在文案中称为“精确恢复刚才读到的那一行”。精确可见楼层或偏移的恢复属于后续完善目标。

用户带指定楼层进入时，不被历史进度覆盖。页面刷新、异步图片和头像补齐不能把当前阅读点反复推走。

### 11.7 对话与全文搜索

查看对话保留中心楼层、上下游关系、进度与跳回楼层；全文搜索保留关键词、是否包含引用、作者与 UID／表情编号匹配、命中摘要和定位。

两者存在原生入口，但尚不等同桌面版完整缓存、暂停继续、跨帖多父引用与共享队列能力：

- 当前对话读取最多 50 页，不能把这个范围内的结果写成全帖完整对话。
- 搜索逐页读取与读取范围必须可见，支持停止；退出后是否保留进度按实际能力说明，不伪称已经跨打开恢复。
- 后续完善时加入共享缓存、串行限速、失败续读和清楚的局部结果；以未缓存页面至少约一秒间隔为目标，不能为手机流畅而密集扫全帖。
- 未读、缺失、删除、超出范围与无权限分别说明。
- 显示“已读取 12 / 50 页，找到 8 个楼层”等真实状态，而不是提前显示“已搜索全文”。
- 点击命中后返回来源位置；关闭读取任务不清除正在编辑的草稿。

### 11.8 阅读投票与提交

投票组件保留选项、已选状态、最多可投数量、参与人数、截止时间、已投记录及结果。长选项正常换行，整项可点，不能把百分比与说明压成 10 号小字。

- 未登录、不可投、已投、已过期和提交中分别有准确状态，不把不可选都表现成没有解释的灰色。
- 保留最多选择数量及取消选择；到达上限时说明原因，不静默忽略下一次点击。
- 要求投票后可见时，未满足条件不能展示票数、百分比或结果条；可见性以服务端返回状态为准。
- 当前结果比例采用单项票数除以参与人数的口径。多选时各项比例相加可能超过 100%，不能为图形好看擅自改成“占总票数”；如需另一个口径必须单独命名。
- 未取得人数或票数时不把缺失值显示为确定的零。提交成功后读取真实结果，失败保留可恢复的选择，结果未知不自动重投。

## 12 正文渲染与媒体

### 12.1 原生 UBB 与 Markdown

保留已有行内格式、颜色、字号、链接、引用、代码、列表、表格、对齐、图片、附件、Markdown 块与原样文本。Markdown 内容按对应文档语义渲染，不把行内解析当作完整文档能力。

不能正确解释的语法保留原文或提供网页查看，不静默丢弃正文。当前数学内容以代码样式展示，不将其写成已经具备完整公式排版；精确公式渲染列为待接入。

引用的缩进每级约 12，视觉深度最多约两级，更多层级用标记和展开维持关系，不能让中文缩成窄列。长引用可折叠，但受限内容不能借展开绕过权限。

### 12.2 表情

保留正文约 40 逻辑点最大边的大表情方向，不把“表情放大”变成整段文字双倍字号。基线、行高与连续多表情自然换行，不能裁切或压住上下行。

当前选择器有 AC、CC98、EM、MS、TB 五类，以及最多 24 个最近使用项。保留全部已有类别与最近使用，不沿用旧规范中“原生已有六组”的描述。深色 AC 亮色资源适配保留。

表情选择器每项触控至少 44，缩略图可约 30；标签与编号可被朗读。选择后插入原始编号，光标停在插入内容之后。找不到资源时显示可识别的原编号，不能统一换成另一个 emoji 冒充原表情。

### 12.3 图片查看器

保留正文图片、图集前后切换、缩放、拖动、保存和分享。

- 正文图片保持比例和内容宽度，不强制裁成新帖封面。
- 隐藏图片先显示明确查看动作，不能在正文、图集、搜索或缩略图里提前泄露。
- 未放大时左右切换，放大后拖动当前图；显式关闭与前后操作始终可达。
- 放大、双击、单击控制层、返回和左右滑动不能互相抢占。
- 超长图提供合适预览和完整查看；失败只影响单图，允许重试。
- 保存照片仅在请求时使用相应系统权限，拒绝后仍可阅读或使用合法的文件分享路径。
- 动态图片能否保持动画按实际渲染能力说明，不能因资源是 GIF 就宣称原生已经完整动画播放。

### 12.4 代码、表格、音视频与附件

代码可选择与复制，行号不进入复制内容。宽表格局部滚动或展开，不缩到看不见字。未知内容不生成虚假下载框。

当前音频、视频与 B 站内容主要提供媒体链接和外部打开，不称为已有内嵌完整播放器。继续保留真实标题／链接，后续播放器接入需要独立交互与状态。

附件明确“打开链接”“开始下载”“临时下载完成”“保存到文件”的区别。当前原生 Link 打开不等于旧壳的下载管理器已经接通；没有完整下载能力时不展示虚假的保存完成。

## 13 发帖回复与编辑

### 13.1 保留当前原生输入架构

现有核心是 UITextView 承载的 UBBTextEditor、选区控制器、双行格式工具及可展开预览。保留这条原生输入路径，不重新依赖网页 DOM，也不为了排版统一改成未经实现的所见即所得编辑器。

任务分为发主题、发投票、普通回复、引用回复、编辑已有帖子。顶部为返回／取消、任务名称和一个主提交动作。

当前发主题同时有顶部发布和底部发表，后续统一一个主要提交入口，不能因为有两处按钮产生重复任务；长表单需要底部提交时可使顶部变为定位或状态入口，但不同时突出两个主按钮。

### 13.2 编辑区与双行工具

保留粗体、斜体、下划线、删除线、字号、颜色、对齐、引用、代码、链接、列表、表格、分割线，以及 Markdown 格式工具。

双行分组建议为：

1. 常用文字格式及字号／颜色／对齐。
2. 引用、代码、链接、列表、表格和分割线等结构操作。

行内横向滚动必须有可发现的边缘提示；大字时可合并低频项到格式面板，但不得删去已有功能。表情、图片、文件作为独立输入工具组，与格式工具相邻，不散落成多个小按钮。

键盘出现时只保留编辑所需控制。编辑器在一个主要滚动上下文中工作，避免页面、UITextView、半屏面板三层抢滚动。可展开预览独立于编辑区，普通编辑不同时强制显示上下双区。

### 13.3 选区与输入法

- 有选区时格式包裹实际选中文字；无选区时把插入点放进成对标签之间。
- 插入表情、图片或附件后，光标在插入内容后，不跳回首行或随机旧位置。
- 工具操作后保留合理选择和撤销路径，不能通过重建整个输入控件实现“更新”。
- 中文组词期间不覆盖 marked text，不因外部绑定更新丢掉候选；必要的模式切换等组词完成后进行。
- 编辑期间自动滚到插入点，但不在用户手动选择另一位置后强行把光标拉回旧选区。
- 关闭表情或文件选择器后继续原来的任务，不新建一份草稿。
- 回车默认换行，不等同发帖；发布由明确按钮触发。

### 13.4 主题与版面条件

保留选择发布版面、上次发帖版面、普通／投票入口、一级二级标签、UBB／Markdown、回复通知、帖子类型及匿名条件。

默认布局：账号与版面 → 标题 → 正文与工具 → 草稿及预览 → 版面所需标签／类型／匿名与通知设置。需要发布前理解的收费与强制条件靠近提交摘要，不藏进折叠菜单。

- 从版面进入时已有版面，不强迫再选一次；从新帖进入提供版面搜索及上次发帖入口。
- 当前匿名值为强制、可选或不允许的不同条件，显示对应解释，不用一个无条件开关。
- 当前可选匿名文案包含消耗 10000 财富值。必须与服务端实际规则一致；后续费用变化以最新站方规则为准，不能把旧文案当扣费保证。
- 保留普通帖、学术通知与有权限时的校园活动；读取权限中不等于无权限。
- 一级标签改变后清楚处理二级选择，不在用户不知情时发送已经失效的二级标签。
- 当前客户端正文按 8000 字符校验，应显示包含最终附加内容的计数与限制；服务端校验仍是最终结果，不凭 UI 字数条保证发布成功。

### 13.5 回复与小尾巴

保留普通回复、引用内容、原楼层链接和 parentId 关系。引用对象的作者／匿名、时间、楼层与原内容要准确，不能在修改排版时丢掉引用关系。

保留当前小尾巴开关及默认开启的偏好，但在编辑区或提交摘要可感知“将附加小尾巴”，不能提交后才发现。匿名或敏感版面是否禁用必须沿用相应站方与原插件约束；当前回复上下文尚需补齐，不把自动停用写成已实现。

若尾巴导致超限，在提交前指出原因并允许调整；用户关闭尾巴不影响正文，不因保存设置重载编辑器。

### 13.6 图片与附件上传

保留系统照片选择与文件选择，以及选中后上传并插入 UBB 的既有流程。选择照片本身即会发起上传，应在入口或选择前有清楚提示，不能让用户误以为文件仍只在本地。

当前单项上传采用活动状态；后续只有取得真实传输数据才显示百分比。多选和后台续传不是现状，不放“批量自动上传完成”的文案。

每项上传应有文件名或缩略图、进行中、失败、重试和移除。取消选择不上传，不插入空标签。预览切换不重复上传；已上传链接与尚未完成文件分别处理。

提交前有上传未完成时，说明等待原因，不生成不完整引用。系统文件访问失败保留正文和其他文件；App 进入后台不承诺持续传输。

### 13.7 草稿

保留自动保存、手动保存、恢复、清除，以及回复和编辑草稿。统一放在“草稿”菜单与保存状态行，不把保存、恢复、清除和状态提示挤在一条窄行。

- 已保存必须对应真实落盘结果。当前存储吞掉写入错误，后续不得仅凭点击按钮显示成功，见第 24 节。
- 恢复前显示任务对象和保存时间，避免直接覆盖正在写的内容。
- 普通主题、投票、回复、引用回复、编辑按账号和任务对象区分；当前普通主题与投票共用版面草稿键，列为待完善，不视为设计目标。
- 草稿清除与清空编辑区是不同动作，按钮标明范围；清除后正在编辑的输入是否保留需明确，不能无提示丢掉两份。
- 退出有变化的任务时，提供继续编辑、保存并退出、丢弃修改；暂时不支持可靠保存时可复制内容，不伪称已经保存。
- 上传资源与临时文件不等于草稿全部可恢复。重启恢复不承诺系统待上传文件仍有权限。
- 服务端确认成功后才清除对应草稿；超时、退后台与提交结果未知不清除。
- 草稿中心是待新增入口，当前不能把已有分散的草稿保存称为已经有完整草稿管理器。

### 13.8 投票、@ 提醒与编辑

投票保留 2–20 项、每项当前最多 50 字、当前 1–1000 天、最大可投数和投票后结果可见。约束来自本分支客户端实现；真正可发布范围以服务端为准，出错时保留全部选项。

@ 提醒保留当前发帖后的相关通知路径。主题发布成功而提醒失败时，应表达“主题已发布，部分提醒未完成”，不能整体报发布失败引导重发。

编辑既有帖子时保留原内容类型与权限；格式模式不能静默改写内容。资料签名编辑仍是独立资料表单中的 UBB 源码，不宣称已复用完整发帖编辑器。

UBB／Markdown 模式切换目前不是可靠语法互转。后续改变模式前需要明确解释和预览，保留原输入；完整互转另列待接入，不为统一按钮自动转换并覆盖。

## 14 消息与私信

### 14.1 消息分类

保留回复、@我、系统、私信四类。分类名称至少可读，计数是辅助信息，不以 10 号分类字和大计数颠倒层级。

全部已读针对当前消息类型，文案写“将回复全部标为已读”等明确范围；私信没有相同接口时不显示同样可点击的按钮。计数更新失败显示暂无法确认，不归零。

点击通知进入真实主题与楼层。内容或权限已变化时说明原因，保留返回通知列表的路径；不连续弹错后把用户送回首页。

### 14.2 联系人与私信会话

保留近期联系人、头像、可用的摘要、时间、未读、加载更早与发送。联系人置顶当前未在原生主路径完整接入，不将其写成已有功能。

会话默认使用清楚的左右对话气泡，宽度约不超过内容宽的 82%，时间至少 12–13，长消息能选择和复制。UBB 内容保留原有语义，不截掉正文。

- 加载更早保留当前消息锚点，不自动跳到最底部。
- 用户在底部时可跟随自己发送的新消息；用户正在读历史时，新内容只显示提示。
- 发送中防重，失败保留输入；结果未知先核对，不自动重发。
- 不推测已读、已送达、撤回成功和正在输入，只显示服务端确实提供的状态。
- 新私信可从用户主页现有入口进入，目标用户名和账号身份清楚。
- 当前私信输入未形成与帖子草稿相同的持久恢复能力；跨账号、关闭与退后台需补齐保护，不声称已有私信草稿库。

## 15 我的与用户资料

### 15.1 我的页面

顶部保留当前账号头像、名字、称号／简介以及发帖、威望、风评、关注、粉丝入口。统计分组有层级，大字下改为两行或列表，不靠缩放到极小字号维持五等分。

账号切换区靠近身份信息。我的内容保留收藏、稍后再看、浏览历史、我的主题与回复、我的主页、编辑资料和设置。现有“发帖”统计可以继续进入活动页，同时在内容列表提供清楚的“我的主题与回复”名称，避免入口只藏在数字上。

### 15.2 个人主页、关注和粉丝

保留公开资料、签名、主题列表、关注／取消关注和私信；资料加载与主题列表加载分开，局部失败不抹掉全部页面。

我的主题与回复保留 UBB／Markdown 展示及站内链接处理。点击回复进入对应楼层，不能把原回复摘要误当成主题正文。作者头像缺失用现有本地默认头像，匿名沿用专用头像，不能展示错误的实名回退。

### 15.3 编辑资料与头像

保留头像、性别、生日、QQ、邮箱、简介与 UBB 签名输入。长表单按资料、简介、签名分组，常驻标签替代只靠占位。

头像上传是立即生效动作，其他字段由保存提交，必须明确区分；点击返回不能让用户误以为刚改的头像也被取消。头像上传失败保留旧头像，其他输入不重置。

保存时保留未编辑字段，不为简化表单把称号等服务端数据清空。签名预览可后续增加，但当前源码输入必须保留，不能写成已有双向编辑与表情工具。

## 16 本机内容与屏蔽规则

### 16.1 收藏与稍后再看分开

收藏是 CC98 服务端内容，保留分组筛选、新建分组、移入分组、取消收藏和分页。入口显示当前分组，不只藏在文件夹图标后；移动分组有显式菜单，不只靠长按。

稍后再看是本机按账号保存的主题条目，保留加入、移除、打开与清空；当前没有完整的已读管理、搜索与导入导出，不写成已有。取消加入提供轻量撤销，清空先确认当前账号与范围。

### 16.2 历史、备注与进度

本机历史当前保留最近 200 个主题，重访更新顺序；页面说明是本机历史，不冒充原站全部足迹。删除前不暗示可以同步删除站方记录。

主题备注按主题 ID 保存，当前最多 500 字；保留在主题更多中编辑与恢复。它不是旧插件最多 80 字的用户备注，不能复用同一个名称或迁移规则。用户备注待接入时另有独立数据结构和入口。

浏览进度与草稿各有任务含义。清空历史不顺手清草稿、备注、收藏和令牌；要合并清理时必须先明确范围。

### 16.3 屏蔽种类全部保留

管理页面保留用户 ID／用户名、版面 ID／名称、主题 ID、标题、正文内容及数值条件。分成可进入的分类或明确章节，避免同时堆在一个极长 Form 中。

添加输入与已保存规则分开；每条规则可查看完整表达式、编辑或删除。规则无效显示错误位置，不允许保存后悄悄失效。

### 16.4 规则语义与当前差异

当前原生规则包含文本、部分正则、出现次数比较及独立数值条件。它没有完整继承桌面版 AND／OR／NOT 与括号表达式，不能原样把桌面帮助文案贴成原生能力。

需明确补齐的含义：

- 现有页面提示 /正则/i，但解析器主要识别首尾都是斜杠的形式；界面提示和解析能力必须一致。
- 版面 ID 应精确匹配，名称匹配规则要说明，不让 ID 的部分字符串误命中其他版面。
- 正文匹配与引用、签名的范围需要一致；用户屏蔽不能把其他作者正文或不相关引用一起删掉。
- 赞、踩、总数与比值缺失不能当成已知零。目标比值为赞除以踩，有赞无踩为无限大，零赞零踩或未知不判定；当前实现不同，列为明确口径修正目标。
- 风评只统计完整范围内的风评变化，不把财富等记录算进去；记录表和筛选使用同一口径。
- 后续支持复杂正则与高级表达式时有资源限制与错误反馈，不在主线程无界匹配，也不把正文传外部服务。

命中楼层以“已按你的规则折叠”展示，提供原因和临时查看；临时查看不删除永久规则，不越过原站权限。列表因过滤变空时说明“当前已加载内容均被筛选”，仍允许继续读取或调整规则，不冒充本版没有主题。

## 17 原生登录与多账号

### 17.1 不再采用旧网页绑定流程

正常入口是“使用 CC98 登录”进入系统 OpenID 授权；原生 API 使用该会话。用户无需先在旧壳网页登录再另点同账号绑定，界面不再出现重复的两步绑定遮罩。

现有客户端和回调继续使用 org.cc98.reborn.shell:/oauth/callback。系统窗口可能保存其他账号，但原生用户身份以本次令牌所取得的资料为准，不拿旧网页 UID 作为日常原生登录的第二套状态。

令牌按账号保存在 Keychain；界面和隐私说明不得继续称“只保存水印摘要、授权后立即丢弃所有 token”。密码不由 App 保存，令牌也不出现在 URL、日志、分享、剪贴板或配置导出中。

### 17.2 账号状态

| 状态 | 主要表达 | 可用动作 |
| --- | --- | --- |
| 正在恢复 | 正在恢复本机登录 | 可浏览确实公开的内容，不并发新建多套授权 |
| 未登录 | 使用 CC98 登录 | 系统授权；公共页面正常返回 |
| 登录或添加中 | 正在等待授权 | 系统取消，防止重复请求 |
| 可用会话与资料已取得 | 当前账号名与头像 | 正常业务及账号管理 |
| 访问令牌到期、仍可续期 | 必要时显示正在恢复会话 | 自动刷新，通常不弹登录窗 |
| 刷新凭证确定失效或未获续期授权 | 当前账号需要重新登录 | 重新授权，保留账号条目与本机数据 |
| 网络暂不可达 | 暂时无法确认登录状态 | 恢复网络后重试，不自动删除账号 |
| 切换中 | 正在切换到某账号 | 暂停相冲突操作，保留来源 |
| 切换失败 | 未能切换，仍使用原账号 | 重试或重新登录目标账号 |

恢复成功必须同时有当前资料、活动账号与可用会话，不能只凭状态枚举显示已登录。长时登录候选已补上恢复时的资料回填；冷启动与离线恢复仍需按第 23 节真机验收。

### 17.3 添加、切换和失败回退

保留当前“添加账号”“选择已保存账号”“当前账号标记”和“移除其他账号”。添加新账号使用现有独立授权方向，不把当前账号悄悄覆盖掉。

账号列表应在登录恢复失败时仍可到达，让用户选择其他账号或重新登录，不只剩一个无上下文登录按钮。

切换成功前不提前把所有页面当作新账号。失败恢复前一个账号的身份、令牌和当前数据；UI 明确仍在使用谁，不能让头像、账号勾选与实际发帖身份各不相同。

### 17.4 退出与移除

当前“退出当前账号”移除其本机凭证及账号列表项；如有其他保存账号会尝试切换。确认文案要说明这个行为，不能让用户以为退出后全 App 必然变未登录。

退出不等于撤销站方授权，也不表示退出系统 Safari。当前移除账号不会同步删除其本机资料文件；界面不能写“所有数据已删除”。

若后续提供“同时删除此账号本机数据”或“退出所有账号”，作为独立且明确的高风险动作，列出草稿、备注与历史影响；当前没有对应入口时不画成已有能力。

### 17.5 长期免重复登录的目标

默认保留当前按账号记住本机登录的方向。在刷新授权有效、站方允许且校网可达时，访问令牌到期应由 App 自动取得新令牌，不要求用户重新输入密码或重复同意。退出重开、锁屏、暂时断开 VPN 本身不表示授权失效。

不把 access token 设计成永不过期，也不修改 expires_in、JWT 到期时间或设备时间来伪装有效。需要延长的是用户可持续使用的会话体验，而非让服务器接受已经过期的凭证。

普通访问令牌到期、刷新凭证失效、网络错误和本机存储错误必须分开。只有确认需要新的用户授权时才进入重新登录；即使如此也保留账号条目、草稿、备注和其他本机内容。

### 17.6 已确认的后台页面与应用侧缺口

用户于 2026 年 10 月 20 日提供的现有客户端页面显示：

| 项目 | 页面显示 | 对长期登录的意义 |
| --- | --- | --- |
| 脱机访问 offline_access | 已勾选 | 客户端页面允许申请该领域；App 仍需实际请求并获得授权 |
| 访问令牌有效期 | 01:00:00，即 1 小时 | 应自动续期，不应每小时重复登录 |
| 身份令牌有效期 | 00:05:00，即 5 分钟 | 不是原生 API 会话必须每 5 分钟退出的依据 |
| 刷新有效期模式 | 滑动有效期 | 实际成功刷新后按服务端策略延展可用窗口 |
| 固定有效期 | 30.00:00:00，即 30 天 | 不能据此承诺滑动可以无限延期，需确认是否作为绝对上限 |
| 滑动有效期 | 15.00:00:00，即 15 天 | 不等于应用不运行也能无限保活 |
| 重用刷新令牌 | 未勾选 | 页面说明为刷新后签发新令牌；App 必须接住并安全保存新值 |
| 应用审核 | 尚未通过，页面提示授权时间和次数受限制 | 实际有效策略可能进一步受限，长期承诺需站方确认 |
| 修改令牌安全设置 | 仅受信任应用可修改 | 不能把自行改时长作为当前用户可完成的普通设置 |

截图确认的是页面显示，不代替配置已保存、缓存已更新或真实签发结果。若刚修改选项，应通过页面提交保存；不需要为试用长期登录先关闭用户确认、打开重用刷新令牌或把客户端密钥打包进 App。

原始 DeepSeek 基线只请求 openid、profile、cc98-api、read-user-info。长时登录候选已为原生授权追加 offline_access 与 consent；真实服务器是否签发可用刷新凭证仍需首次授权验证。

原生长期登录保持现有授权码与 PKCE，并满足离线访问所需的用户同意；新增范围可能需要用户进行一次授权。只扩展需要长期业务访问的原生流程，不顺带改变旧摘要绑定或其他实验功能的授权用途。[OpenID Connect 离线访问](https://openid.net/specs/openid-connect-core-1_0.html#OfflineAccess)

对固定 30 天与滑动 15 天，按常见 IdentityServer 语义，滑动窗口不能越过绝对生命周期；这是一项解释该配置的参考，不是已确认 CC98 当前服务端实现或该未审核应用实际期限。若希望持续数月免交互登录，需要站方审核并明确该客户端的长期刷新策略，不能仅靠手机端定时刷新实现。[IdentityServer 刷新生命周期参考](https://docs.duendesoftware.com/identityserver/reference/v7/models/client/#refresh-token)

### 17.7 续期行为与界面反馈

- 回到前台、冷启动恢复或业务请求前，按真实到期时间检查；保留现有约提前 60 秒的检查方向，不为保活频繁请求授权中心。
- 同一账号同时只执行一条刷新链，其他请求等待同一结果；不能让首页、私信、通知各拿同一个一次性刷新令牌并发兑换。
- 刷新返回的新凭证按发起时的账号安全写入 Keychain，再更新会话；旧响应不能覆盖新令牌或串到另一个活动账号。
- 页面显示账号与资料保持稳定；短暂续期通常不打断阅读，只有确需等待当前操作时显示“正在恢复会话”。不把每次续期都弹成登录窗口。
- 离线、DNS、VPN 不可达、超时或服务暂时错误不删除已保存账号与凭据；恢复网络后提供受控重试。不能把所有失败归为“登录过期”。
- 服务器确认刷新授权失效时，当前账号标记“需要重新登录”；不反复重放已失效的刷新令牌，不自动切到另一个账号代替执行原操作。
- 刷新后保存失败说明“登录状态未能安全保存”，不伪称续期成功，也不误报网络错误；本机业务数据仍保留。
- 明确的身份拒绝可触发一次受控恢复；发帖、投票和私信的提交结果未知不能因续期而盲目重发。
- iOS 后台持续运行不是前提。App 关闭后不以定时任务冒充持续在线；下次打开仍在服务端有效窗口内时再恢复。
- 不保存密码用于定时自动登录，不用反复强制授权刷掉服务器期限。无法取得有效刷新授权时，系统重新授权是明确的后备路径。

一次性轮换与安全存储共同保护长期会话；长期保留令牌不能意味着重复使用已被服务端消费的旧值。[OAuth 刷新令牌保护](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)

### 17.8 长期登录与水印

水印来自当前原生资料，随账号切换更新；资料读取失败不沿用另一账号。网页兼容页不是原生登录状态的证明，不自动复制凭据解决会话不一致。

用户主动退出、移除账号或服务端授权不再有效时，仍按真实身份状态处理。界面不提供“永久登录已保证”开关；可说明“已记住此账号，将在授权有效期内自动续期”。

### 18.2 前台消息检查的真实含义

当前应用活跃时约每 60 秒检查消息计数，计数增加时产生本地通知；退后台会停止轮询。它不是 APNs 远程推送，不提供应用关闭后即时通知的保证。

保留这项能力，用户界面可称“前台新消息提醒”，并说明需要校网／VPN、有效账号与系统通知许可。不要使用“后台实时通知”文案。

### 18.3 通知权限与点击行为

首次启动不为尚不了解用途的用户立即强制弹权限窗。后续改为在启用提醒时先简短解释，再由用户触发系统请求；这是对现有启动请求方式的交互完善，不表示提醒功能被删除。

设置区分：未询问、系统允许、系统拒绝、App 内关闭、账号不可用。拒绝后仍可使用消息中心，提供打开系统设置的真实路径，不反复弹授权。

通知只包含类别和必要数量，默认不携带私信正文。点击进入对应账号和消息类别；如果账号已移除或会话失效，先处理身份，不把旧账号通知引到新账号的消息。

当前版本显示不等于已经有原生更新检查。后续提供获取新版 IPA、自签与续签帮助时，区分查看版本、下载文件和安装成功；不沿用桌面“覆盖扩展 ZIP 即更新”的含义，不承诺 App 自动安装或个人签名永不过期。

## 19 错误状态与操作结果

### 19.1 页面和组件必须定义的状态

每个页面至少有初次加载、成功、空、局部失败、整页失败、权限不足。输入任务增加校验失败、上传中、提交中、确认成功、结果未知；账号增加恢复、过期、添加和切换失败。

| 场景 | 建议表达 | 恢复与保护 |
| --- | --- | --- |
| 网络不可达 | 暂时无法连接 CC98，请确认校网或 VPN 可用 | 重试读取，保留已加载内容 |
| 超时 | 本次连接超时 | 区分读取与提交，不自动重发 |
| 需要登录 | 当前操作需要登录 | 进入系统授权，保留任务上下文 |
| 访问令牌到期、可刷新 | 正在恢复会话，仅必要时显示 | 自动续期，不清账号，不打断无关阅读 |
| 刷新授权确定失效 | 此账号需要重新登录 | 保留账号条目与本机数据，不冒充用户主动退出 |
| 权限不足 | 当前账号无法执行此操作 | 说明对象与返回路径，不反复自动重试 |
| 内容删除或不存在 | 内容已删除／未找到，按真实结果 | 返回来源或其他楼层 |
| 新帖达到读取范围 | 已显示本次可读取的最新内容 | 可刷新或进入版面，不虚构全站终点 |
| 过滤后没有可见项 | 当前已加载内容均被你的规则筛选 | 继续读取或管理规则 |
| 图片／缩略图失败 | 此图片暂未加载 | 单项重试，列表和正文继续可用 |
| 登录取消 | 已取消登录，当前账号未改变 | 正常返回，由用户主动重试 |
| 切换失败 | 未切换成功，仍使用原账号 | 目标账号重试或重新授权 |
| 草稿落盘失败 | 尚未保存到本机 | 重试或复制，不清原输入 |
| 发布成功但 @ 失败 | 主题已发布，部分提醒未完成 | 查看原帖，避免重发主题 |
| 提交结果未知 | 结果尚未确认，请先检查原帖／会话 | 保留草稿，不自动再次发送 |
| 语法不能完整呈现 | 此部分暂不能完整渲染 | 保留原文或主动打开网页 |
| 当前原生未接入 | 具体能力尚未接入 | 不显示虚假开关或成功状态 |

### 19.2 加载与提示

有旧内容时，顶部或局部显示更新状态，失败不整屏覆盖。骨架应像真实列表或楼层，不展示虚构帖子。轻提示可用于成功，但权限、保存失败和提交未知必须能持续找到。

统计、头像、缩略图和签名可分别失败，不能一个字段失败就将账号退出或清掉全页。必要账号资料缺失与可选头像缺失分开处理。

### 19.3 术语

“登录／重新登录”“添加账号”“切换账号”“退出当前账号”“移除本机账号”分别使用；不再用旧壳“解除绑定”指代原生退出。

“收藏”“稍后再看”“主题备注”“用户备注”“草稿”各指一个对象。当前没有网页同步行为的原生页不显示含义不明的“同步”按钮，刷新只做实际读取。

## 20 无障碍隐私与动作边界

### 20.1 无障碍

主要流程必须支持 VoiceOver，作者、楼层、正文、评分与操作按合理顺序朗读。水印、装饰线和重复图标不制造朗读噪声。

图标按钮有动作名与当前状态，不能只读出一个计数。更多菜单、楼层链接、格式工具与卡片动作均可显式操作，不依赖滑动或长按。

支持大字、加粗文字、提高对比、减少透明度和减少动态效果。面板打开焦点进入，关闭回触发控件；网络提示不反复抢走正在输入的焦点。

主题阅读、图片选择、编辑工具与账号切换都不能形成键盘或辅助技术无法退出的陷阱。

### 20.2 隐私与凭据

只在用户动作需要时调用照片、文件和通知权限。系统拒绝不阻断无关能力。导入与读取剪贴板由用户主动触发，不启动即读取。

凭据只通过已批准的安全会话和 Keychain 使用；发帖、分享、截图诊断与数据导出不带 token、授权码、完整回调或私信正文。原生会话不通过页面重排扩大给外链。

当前本机数据不默认跨设备同步。涉及备份、账号移除或清理时说明实际保存范围，不宣称系统卸载、自签续期或更换 Bundle ID 后一定自动恢复。

## 21 动效与性能体验

以下是交互目标，不是已测得的成绩：

- 按压与执行状态约 100 毫秒内出现；业务结果以实际响应为准。
- 页面和面板使用系统过渡，通常约 180–280 毫秒，不额外给每个楼层加飞入动画。
- 减少动态效果时取消大幅平移、弹跳、视差与闪动骨架。
- 为图片、缩略图和异步统计保留合理空间，避免反复跳动。
- 长帖可按需渲染，但楼层定位、选区、返回和无障碍顺序不能失效。
- 后台读取不能阻塞中文输入与工具操作；不为所有数据回包重建编辑器。
- 请求复用、取消与缓存不能跨账号混用私有内容。
- 关闭图片、详情和任务后释放无用资源，不为五栏保留无限套页面和播放器。
- 触觉只辅助明确选择、成功与风险，不在滚动、每次翻页或每个计数变化时连续振动。

## 23 设计交付与验收

### 23.1 必须覆盖的页面

五个根页面及相应导航状态；版面详情与大字报；新帖两种视图和筛选；帖子首末页、长标题、普通与匿名楼层、签名、评分、投票、分页和跳楼；图片与媒体回退；对话与全文搜索；搜索与用户结果；所有编辑任务及上传草稿；四类消息与私信；资料、关注、粉丝、收藏、本机内容、规则、设置及多账号。

每页必须覆盖正常、初次等待、空、局部失败、权限或身份相关状态。编辑另有键盘、选区、取消、未保存、上传失败和结果未知。账号另有恢复、过期、添加、切换与失败回退。

### 23.2 必须走通的流程

1. 冷启动恢复 → 资料和活动账号一致；断网恢复 → 仍能选择账号或重试。
2. 添加第二账号 → 切换成功 → 切换失败回退 → 退出当前及保留其他账号。
3. 十大／新帖／版面 → 原生主题 → 翻页与跳楼 → 引用或通知定位 → 返回来源。
4. 新帖列表 → 卡片 → 更换全部／图文 → 继续加载 → 大字单列回退，数据和位置保持。
5. 主题 → 普通与引用回复 → 表情／格式／上传 → 草稿 → 发送成功、失败和结果未知。
6. 发主题与投票 → 版面和标签 → 匿名与类型条件 → @ 提醒部分失败，不重发主题。
7. 我的回复 → 正文链接 → 主题对应楼层 → 返回原回复列表。
8. 私信加载历史 → 保留阅读点 → 发送失败保留输入 → 账号切换保护。
9. 评分、投票、隐藏图片和屏蔽 → 数字与权限正确，展开不泄露。
10. 收藏分组 → 稍后再看 → 主题备注 → 清空单一范围，不影响其他数据。
11. 前台提醒拒绝／允许 → 通知点击 → 正确账号与消息分类。
12. 深浅色、大字、VoiceOver、横屏与键盘下完成阅读、编辑和账号操作。
13. 获得长期授权后，连续跨过至少两个真实访问令牌有效期，阅读与操作不要求重新登录；同时验证重启、断网恢复、并发刷新和多账号切换。
14. 刷新授权不可用或确定到期时，仅要求对应账号重新授权，账号记录与草稿仍在；不将 15 天滑动或 30 天页面值宣称为已实测长期上限。

### 24.2 设计与实现的推进顺序

1. 先完成长期登录：首次授权、恢复、自动续期、轮换存储、账号隔离、断网恢复与真实失效处理；取得云端生产代码检查与真机验收证据。
2. 按已确定的五栏、标题层级、主题行、卡片、楼层与底部控制组整理 UI。
3. 覆盖编辑键盘、草稿、上传与消息，以真实状态驱动页面。
4. 整理评分、投票、屏蔽、收藏和本机内容，统一数字及数据范围。
5. 最后按第 22.2 节补桌面增强和独立实验能力，不用新增功能掩盖现有输入与身份缺口。

新增或改动必须同时更新入口、数据归属、权限、加载失败、返回和验收对象。改变默认值、账号范围、规则口径或保存范围，要写清迁移，不能只改一个 UI 名称。
