# CC98 Reborn 手机端 UI 设计规范

版本：1.0  
日期：2026 年 10 月 19 日  
适用产品：CC98 Reborn 独立 iOS App  
设计基线：Reborn 0.4.1 功能与 iOS 壳 0.2.0 能力  
状态：手机端设计提案，供确认后作为设计与开发基线

手机端采用“原生导航与系统交互 + 本地 Reborn 内容界面”的结构，直接访问 CC98 原站。保留青竹配色、清晰的楼层和完整的论坛功能，用单列阅读、分层操作与独立编辑流程替代桌面侧栏和密集工具条。

本规范确定信息架构、排版、组件、页面、交互、功能去向与验收要求。本轮只产出规范，不修改应用代码，不启动构建或发布。文中“必须”是后续实现的验收要求，“应”是默认采用的设计方式，“可”是满足条件后的可选扩展；这些目标不代表当前 IPA 已经实现。

阅读入口：先看[导航结构](#3-导航与页面结构)与[文字排版](#5-文字与中文排版)确定整体，再按[读帖](#9-帖子阅读页面)、[编辑](#11-发帖与编辑)、[消息与个人内容](#13-消息与个人内容)展开页面；[功能去向表](#19-功能去向与完整性检查)检查是否漏功能，[验收清单](#20-关键流程与设计验收)用于后续逐项核对。

## 1 设计目标与优先级

### 1.1 手机上的主要任务

按以下顺序分配屏幕空间与交互成本：

1. 找到想看的主题，连续阅读，并准确返回原列表位置。
2. 阅读图片、引用、评分与投票，找到指定楼层和相关对话。
3. 回复、发主题、上传和编辑，可靠保存未提交内容。
4. 接收并处理站内消息、私信和关注内容。
5. 整理收藏、稍后再看、备注、屏蔽规则和个人偏好。
6. 处理授权、网络异常、兼容问题和原站恢复。

### 1.2 发生取舍时的顺序

**业务含义与数据安全 → 可读性与可操作性 → 状态清楚 → 连贯体验 → 信息密度 → 装饰。**

不得为了视觉整齐截断正文、缩小主要文字、隐藏权限条件、改变评分含义，或让正在输入的内容丢失。不得为了“保留全部功能”把桌面全部按钮同时塞进手机首屏。

### 1.3 视觉方向

采用克制、明亮、适合长时间阅读的论坛界面：浅灰页面底色、白色内容面、深色文字、青竹主色和蓝色链接。深色模式使用低刺激的深灰面，不以纯黑和发光色营造科技感。

- 首页呈现真实主题，不设置大幅宣传横幅、装饰性数据看板或问候卡。
- 主题列表以标题和讨论信息为核心，普通主题不统一套大圆角悬浮卡。
- 正文使用连续阅读面，楼层之间以留白、分隔线和作者信息区分。
- 色彩用于当前选择、链接与状态，不给每个版面、头像和数据随机着色。
- 不使用大面积渐变、霓虹阴影、持续发光或无信息价值的动画。
- 系统材质只用于适合的原生控制层；正文、引用、表单和错误说明必须有稳定的可读背景。

## 2 产品边界与真实状态

### 2.1 不改变的使用条件

- 直接访问原站，不引入公网页面代理；使用者需要校网或覆盖应用请求的系统 VPN。
- 论坛登录、操作权限、上传与提交结果，以原站为准。
- 原站登录与 Reborn OpenID 绑定是两个独立状态，不能合并为一个“已登录”。
- 原生授权使用现有客户端及已登记回调 `org.cc98.reborn.shell:/oauth/callback`，通过同账号校验后保存绑定摘要。
- 原站模式始终保留，用于未适配页面和增强失败时恢复使用。
- 不把原站禁止查看的内容、匿名身份、隐藏图片或受限回复，通过重排和预览变成可访问内容。
- 不默认承诺系统推送、后台持续扫描、跨设备同步、离线完整阅读或自动上传重试。

### 2.2 当前能力与设计目标分开标注

| 能力 | 当前基线 | 手机端规范要求 |
| --- | --- | --- |
| 原站访问、原站与增强切换 | 壳已有入口 | 保留，并减轻开发工具外观 |
| 本地 Reborn 注入 | 已接入资源快照 | 按手机排版重新组织，不能仅缩放桌面界面 |
| 原生 OpenID | 已实现并生成 Build 10，真实账号闭环待真机验证 | 独立呈现登录与绑定状态，提供取消、重试、重新绑定和本机解绑 |
| 网页编辑、上传 | 继续使用原站业务 | 为手机提供合适布局，并逐项验证原控件行为 |
| 原生下载与分享 | 壳已有相关通道 | 明确区分下载完成、临时文件与保存到文件 |
| 完整插件设置 | 当前嵌入式设置未接通 | 重做为可在手机使用的设置页，接通前不展示可操作假入口 |
| 桌面帖子侧窗 | 当前壳不支持完整增强侧窗 | 手机改用全屏阅读与列表上下文恢复 |
| 查看对话、全文搜索及复杂编辑 | 桌面已有相关实现 | 保留功能目标，按手机容器适配并单独验收 |
| 问号、AI、本地语义服务 | 当前 iOS 未接入 | 默认不在核心界面出现；独立接入后再开放实验入口 |
| 外部与未识别页面 | 不获得增强特权 | 显示真实页面与来源，允许返回，不伪装成适配完成 |

后续界面状态按真实能力呈现：可用、需要论坛登录、需要同账号绑定、当前权限不允许、当前版本未支持。不得统一表现为灰色按钮且不给解释。

## 3 导航与页面结构

### 3.1 四个固定主入口

根页面使用带图标和文字的底部导航，顺序固定为：**浏览、版面、消息、我的**。搜索与发帖是操作，不占主导航名额。这符合标签栏用于顶层导航、工具栏用于当前操作的区分，且每个入口保留自身导航上下文。[Apple 标签栏指南](https://developer.apple.com/design/human-interface-guidelines/tab-bars)

| 入口 | 默认页面 | 二级内容 | 主要操作 |
| --- | --- | --- | --- |
| 浏览 | 十大 | 新帖、关注、精选、主题搜索 | 搜索、发主题 |
| 版面 | 本地置顶与版面分类 | 版面主题列表、版内搜索、版面信息 | 搜索版面、置顶、发主题或投票 |
| 消息 | 站内消息分类 | 回复、提及、通知、私信与会话 | 查看、回复、原站支持的管理操作 |
| 我的 | 当前网页账号与常用内容 | 收藏、稍后再看、草稿、历史、关注、资料、设置 | 账号管理、配置管理、原站恢复 |

未登录或暂不可达时，不移除或重新排序主入口。进入后显示登录引导或网络恢复页面，保持导航结构稳定。

### 3.2 各入口记住什么

- 浏览记住当前分类、已加载范围、第一可见主题及其相对位置。
- 版面记住分类展开状态、搜索词、当前版面与列表位置。
- 消息记住当前分类、联系人位置与会话草稿。
- 我的记住正在查看的子页与筛选条件。
- 保存和恢复必须受当前网页账号约束；账号变化后不能显示上一个账号的私信、草稿、收藏或本地备注。
- 会话恢复失败时回到该入口的合理默认页，并清楚说明；不把错误页面当作恢复成功。

### 3.3 页面分为三种容器

**根页面**承载四个主入口，显示主导航。顶部是当前页面名称及最多两个常用动作。

**全屏任务容器**用于读帖、私信会话、编辑和较复杂的资料编辑。它是覆盖根导航的临时任务，顶部保留清楚的返回或关闭入口；关闭后返回来源位置。任务内可以继续进入同类页面，返回时逐层恢复，而不是一律跳回首页。它不采用桌面 iframe 侧窗，也不要求复制多套网页登录状态。

**底部面板**用于短操作与选择，如楼层菜单、排序、收藏分组、字号、表情分类和楼层跳转。任务需要长时间阅读、连续输入或多级导航时，应展开为大面板或全屏，不把完整页面塞进半屏。

采用全屏任务容器的原因是：读帖和编辑需要上下文工具条；直接叠在根导航上会同时出现两排底栏，压缩阅读和键盘空间。进入任务后必须能明确返回，不能靠隐藏手势猜测出口。

### 3.4 顶部与底部只各有一个控制所有者

- 适配完成的页面不得同时出现壳顶栏、桌面论坛顶栏和移动标题栏。
- 原生层负责系统安全区、任务容器、返回关闭、系统分享、授权窗口与原站恢复入口。
- Reborn 内容层负责版面与主题信息、楼层、业务操作、编辑工具和内容状态。
- 原生与内容层共享一套页面上下文和操作状态，不分别维护两套互相矛盾的标题、收藏或账号状态；控制所有者负责安全区与键盘占位，另一层不得再次添加同一份内边距。
- 导航容器的变化不扩大增强桥权限：外链、系统授权页和未登记子框架不能因为显示在 App 内就获得主页面能力。
- 页面未准备就绪时，先显示稳定的控制层与加载框架；接管成功后替换内容，不闪现桌面顶栏。
- 顶部标题不能同时使用大标题和另一排重复的小标题；帖子完整标题属于内容区，顶部只保留短标题或阅读位置。
- 同一屏幕只显示一条底部主操作栏。图片查看、编辑和读帖各自替换当前任务工具栏，不能继续堆叠。

### 3.5 返回、外链与深链接

- 返回优先关闭当前临时面板，再退出当前任务；不可一次跨过多级页面。
- 有未提交输入时，返回、关闭、切换模式、重载和切换账号均执行草稿保护规则。
- 同帖页码与楼层链接在当前阅读容器内定位；跨主题链接进入下一个阅读页面，返回后恢复来源楼层。
- 外部链接使用系统网页容器或明确标注来源的原站窗口，不注入 Reborn 特权，也不静默离开 App。
- 从外部打开主题链接时，先进入正常根结构，再呈现主题；关闭后有明确的“浏览”落点。
- 仅恢复已有查看权限的内容；链接失效、内容被删除或权限变化使用各自错误状态。

## 4 尺寸与响应式布局

### 4.1 逻辑尺寸而非截图像素

主设计稿采用 **402 逻辑点宽**，同时检查 320、375、393、430 的窄屏布局。实际布局以系统报告的可用宽高和安全区为准，不写死某一机型的状态栏、灵动岛、键盘或 Home 指示条高度。

原生使用逻辑点；网页以正确的移动视口和可缩放字体建立对应视觉尺寸，不把原生 pt 机械换成 CSS 的 pt 单位。设计稿数值是默认排版基准，不是阻止系统文字放大的固定高度。

安全区、方向变化、放大显示和动态文字都属于适配条件，而不是设计稿之外的例外。[Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)

### 4.2 宽度与间距

| 项目 | 默认规范 |
| --- | --- |
| 手机左右内容边距 | 16；320 宽时可减至 12 |
| 楼层与列表内部水平对齐 | 作者、标题、正文和操作尽量沿同一内容边线 |
| 基础间距级别 | 4、8、12、16、20、24、32 |
| 同一行图标与文字 | 6–8 |
| 同组表单间距 | 12–16 |
| 不同内容组间距 | 24；长表单可用 32 |
| 通用主要按钮高度 | 最小 48，可随文字与辅助说明增长 |
| 通用列表操作行 | 最小 52；多行时自然增长 |
| 图标可见尺寸 | 常用 20–24，触控范围不随图标缩小 |
| 通用独立触控目标 | 最小 44 × 44，适用于图标按钮、分页、关闭与菜单 |
| 相邻独立触控目标 | 默认至少 8 间隔；系统标准控件按系统布局 |
| 内容面圆角 | 12；输入框和紧凑控件 8；胶囊仅用于标签和明确的胶囊控件 |

正文内文本链接随文本流排版，不强行扩大为 44 高的空白块；不得在同一短语内密集叠放多个难以区分的点击区域。独立按钮使用上述更大的项目触控标准。

正文不再叠加第二层卡片内边距。例如 402 宽、左右各 16 时，正文的主要可用宽度是 370；引用可以内部缩进，但不能让整篇帖子因“外卡片 + 内卡片”反复损失行宽。

### 4.3 不同可用宽度的行为

- 小于 600：单列；不保留左右桌面栏，不并排放两个长文本编辑区。
- 600–839：仍优先单列，正文最大阅读宽度 680；两侧留白不用于强塞次要信息。
- 840 及以上：后续可扩展列表与详情双栏，但不作为首轮 iPhone 设计的必交项。
- 横屏沿用同一信息结构，控件按实际高度重排；不因横屏强制进入桌面模式。
- 全屏页面本身不得横向滚动。代码、宽表格和数学内容可在自身区域横向滚动，并提供可发现的边缘提示。
- 所有固定工具栏必须给内容保留等量空间；最后一行文字、最后一个按钮和最后一条消息不能被遮挡。

## 5 文字与中文排版

### 5.1 字体体系

默认使用 iOS 系统字体及中文系统回退，拉丁字符沿用系统无衬线。代码和明确的源码区域使用系统等宽字体。不得下载外部网络字体作为基本阅读前提。

| 文字用途 | 默认字号 | 默认行高 | 字重与规则 |
| --- | --- | --- | --- |
| 根页面大标题 | 28 | 35 | 半粗体；只在合适的根页面使用 |
| 导航栏标题 | 17 | 22 | 半粗体，单行，可用短标题 |
| 帖子完整标题 | 22 | 31 | 半粗体，不限制正文标题的完整展开 |
| 列表主题标题 | 17 | 25 | 中等或半粗体；默认最多 3 行 |
| 楼层正文 | 17 | 28 | 常规；长阅读主基准 |
| 表单、按钮、消息正文 | 17 | 24–27 | 控件高度随内容增长 |
| 辅助说明、时间、版面信息 | 13 | 19 | 使用可读的次要文字色 |
| 短标签与非关键计数 | 12 | 16 | 不承载操作条件、错误或权限解释 |
| 代码 | 14 | 21 | 等宽；支持局部横向滚动 |

项目的 13 号辅助说明下限比系统最小允许字号更保守；不能为了塞下工具条把说明压成 10 或 11 号。系统字体、可放大的文字和足够的字重优先于装饰字体。[Apple 无障碍指南](https://developer.apple.com/design/human-interface-guidelines/accessibility)

### 5.2 正文排版

- 中文左对齐，不强制两端对齐；不默认首行缩进。
- 段落之间留出约半行至一行的间距，不用多个空行制造大块断裂。
- 默认不额外增加中文字距；强调使用合理字重，不连续使用全粗体和强调色。
- 长英文、长链接和文件名允许断行；不为一个长字符串撑宽整页。
- 保留作者有意义的换行、列表与空白，不重排代码或原样文本。
- 引用、公式、折叠内容与附件使用语义块，不把源代码残留混进正文。
- 不给整段正文设置行数截断；“展开全文”只用于明确的预览、引用摘要或签名档。
- 原帖内作者指定的字号、颜色和字体以语义保真为基础；发生不可读对比或越界时提供阅读适配，不能静默抹掉格式含义。

### 5.3 大字与阅读偏好

- 全局界面响应系统动态文字；阅读设置另提供正文大小与行距预览。
- 默认正文 17，紧凑阅读可选 16；更大字号不以 22 为硬上限，必须继续支持辅助功能大字。
- 阅读偏好与系统缩放应合成为一次有效显示尺寸，避免原生和网页重复放大。
- 在 200% 文字放大下，标题、表单和元信息允许增加行数；操作行改为纵向或进入“更多”，不裁字。
- 320 逻辑宽下正文应可单列重排，局部二维内容例外；缩放不能导致主要内容必须左右来回拖动。[WCAG 重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 5.4 名称、数字与时间

- 始终保留原用户名；本地备注在名字后或下方显示，并标记“仅自己可见”，不能冒充原昵称。
- 普通用户名最多两行；匿名内容按原站公开身份呈现，不补充或推断真实用户。
- 楼层使用“1 楼”“128 楼”等清楚标识；标题区与引用跳转保持同一套楼层含义。
- 列表浏览量可使用紧凑数字；打开详情或无障碍读出时提供精确数字。投票结果、评分变动和金额等重要数值不模糊缩写。
- 时间可相对展示，详情提供完整时间与年份；客户端不能把网络错误推断为“刚刚更新”。

## 6 配色与主题

### 6.1 沿用现有语义色

默认配色为现有青竹方案。下列颜色沿用 `src/theme-tokens.css` 的主体系；评分文字的浅色正值单独使用更深颜色，以满足手机小字可读性。

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 页面背景 | `#f6f7f8` | `#16181b` | 根页面和内容组间背景 |
| 主内容面 | `#ffffff` | `#212428` | 正文、表单、主要面板 |

### 6.2 色彩使用边界

- 普通文字与背景至少 4.5:1。本项目标题也以该值为默认目标；必要控件轮廓、焦点和有意义图形至少 3:1。浅分隔线只可作为装饰分组，不可作为唯一的输入框边界或状态提示。[WCAG 文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[WCAG 非文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 链接在正文中使用颜色并提供下划线或其他稳定辨识，不只靠颜色。
- 赞、踩、风评与其他评分遵循原站含义，保留符号、数值和操作名称；不把所有红色都解释为错误。
- 锁帖使用锁图标和明确文案；不在整屏铺高对比警戒纹。
- 主色按钮的文字按实际明暗选择可读前景，不能在深色浅绿按钮上继续套白字。
- 自定义配色要检查正文、按钮、标签、选中态和深色状态；原始选色可保留，实际显示色进行可读性适配。
- 水印沿用可信 `watermarkId` 前八位的身份摘要，不提供随意关闭或伪造入口；不得吞掉点击、破坏选区或阻止 VoiceOver。对水印可读性的取舍需要与原有身份要求共同确认。

### 6.3 保留主题设置的原有含义

- 保留白昼、黑夜、自动三种已有明暗模式；“自动”继续指用户配置的本地时间切换，默认 07:00 白昼、19:00 黑夜。
- 不把已有“自动”静默改名为“跟随系统”。如果后续新增系统模式，必须作为独立选项，并明确保存与迁移行为。
- 首次安装沿用当前白昼与青竹默认值；已有设置优先，升级不重置。
- 保留六组主副色预设与自定义，双色样本旁应有可读名称或编号及选中标记，不只显示色点。
- 界面风格与明暗、配色分开。ASCII / BBS 作为实验风格保留规划：可更换边线、字形和装饰，但不得缩小触控、强制横向滚动或把手机恢复成桌面双栏。
- 更换主题原位生效，不重载编辑器、不丢失草稿、不改变阅读位置；原生控制层与内容层使用一致的已解析明暗状态。

## 7 通用组件与行为

### 7.1 按钮和图标

- 一个局部任务最多一个主按钮；提交、绑定、确认导入等使用明确动词。
- 次要动作使用次级按钮或文字按钮；危险动作使用危险色且远离高频操作。
- 常用动作同时给出图标与短文字。仅图标动作必须有无障碍名称；不能把工具提示或长按作为识别按钮的前提。
- 同一动作在全产品使用同一图标与名称；收藏、稍后再看、关注和置顶必须可区分。
- 优先使用系统符号或成熟的统一线性图标；不混用彩色 emoji、不同线宽图标与装饰插画。
- 点击后立即呈现按压或执行反馈。等待中的动作维持原尺寸，防止按钮移动导致误触。

### 7.2 主题列表行

由“版面或上下文 → 标题 → 作者与时间 → 回复与浏览信息”构成，优先保证标题。

- 主题标题默认最多 3 行；极长标题进入详情完整显示。
- 列表默认不展示正文摘要，不为普通帖子生成无来源的封面。
- 元信息优先级为版面、回复数、最近活动时间、作者、浏览数；空间不足时先省略次要统计，而不是把全部信息缩成小字。
- 未读状态以小标记及可读状态区分，不对整行持续闪烁；未读规则必须有真实数据依据。
- 锁定、投票、置顶、热度等标签只显示实际状态，最多保留必要的两三个；其他状态进入详情。
- 整行打开主题，作者与版面为独立入口；长按可打开辅助菜单，但所有必要操作均有显式“更多”入口。
- 列表行高度随标题和元信息增长；单行标题的普通主题行以至少约 96 为布局起点，多行自然增高，不以固定行高或首屏条数压缩文字。
- 普通行用细线分隔；选中、置顶或错误状态才使用有意义的背景变化。

### 7.3 表单

- 所有字段有常驻标签，占位文字不代替标签。
- 必填、字数与权限限制放在对应字段附近，以原站规则为准。
- 表单验证在字段附近显示；提交失败时滚动到首个错误，保留其他输入。
- 输入与焦点框必须易辨认，不仅靠极浅边线。
- 键盘类型与字段匹配；数学、UID 和页码等字段仍需保留适当的粘贴与纠错能力。
- 表单很长时以自然段和标题分组，不连续嵌套多层卡片。
- 开关旁说明改变的具体行为；不可逆或会清数据的操作不用普通开关表示。

### 7.4 面板与确认框

- 短菜单使用底部操作面板，危险项与普通项分组。
- 可滚动底部面板应有标题、明确关闭入口和足够的展开空间。
- 面板叠加最多一层；需要第二级选择时在同一面板内部前进并返回，不连续堆多张 sheet。
- 未保存输入的面板不允许无提示手势关闭。只读菜单可轻扫或点遮罩关闭。
- 确认框只处理需要明确选择的风险，不用于每次收藏、返回列表和普通查看。
- 确认按钮写真实动作，如“保存草稿并退出”“丢弃修改”“切回原站”，不用泛化的“继续”承担破坏性操作。

### 7.5 提示与进度

- 轻量成功提示不抢焦点、不遮住输入；错误不依赖两秒后消失的气泡。
- 页面错误在页面内出现；上传错误贴近对应文件；授权错误放在绑定区域。
- 可测量才显示百分比，不可测量用加载状态与阶段说明，不编造进度。
- 已有内容时原位显示后续加载失败，不用整屏错误替换可读内容。
- 异步状态应有完成、失败与恢复路径；读取和本地等待可提供取消，按钮不能永久转圈。请求已经发送到服务器后，不把“停止等待”表现为撤回发帖、撤回私信或取消已生效的操作。

## 8 浏览与版面页面

### 8.1 浏览页

从上到下为：页面标题与搜索、发主题入口；十大、新帖、关注、精选四个分类；当前分类列表；根导航。

- “十大”默认单列编号 1–10，完整保留所有可见条目，不为首屏好看只放前五条。
- 排名变化使用小箭头、变化数或文字；不得改变当前原站顺序，不给每一名使用不同彩色卡片。
- 保留首页只显示十大偏好；关闭后追加其他原站模块，以分区标题组织，不恢复桌面双栏。
- 新帖、关注与精选共享列表组件，但各自保留原有排序与筛选语义。
- 分类切换保持控制区稳定；标题较大时可横向滚动分类条，并显示边缘可滚动提示。
- 发主题是明确的编辑动作，不是主导航标签；不使用长期遮挡列表右下角内容的巨大悬浮按钮。
- 下拉刷新只从列表顶部触发，不在读帖或编辑中误触；刷新动作需区分“获取新内容”与“重新整理已加载页面”。
- 新内容出现时提供“有新内容”提示，由用户决定回顶，不在阅读中自动把列表挤走。

### 8.2 版面目录

顶部为版面搜索；接着是“我的置顶”；其后按原站分类展开全部可访问版面。

- 不用复杂九宫格承载大量版面名称，采用清楚的分类标题与列表行。
- 版面名称可两行，简介按需展开；图标不是识别版面的唯一线索。
- 本地置顶显式标明本机属性；置顶操作有按钮和撤销反馈，不依赖拖动或长按。
- 搜索无结果时保留搜索词并可清除；不把“无权查看”混为“搜不到”。

### 8.3 版面主题列表

顶部显示版面名称及“更多”；版面说明、版规与公告作为可展开内容；筛选排序靠近列表。发主题和发投票按当前权限提供入口。

- 公告过长时折叠预览，并保留完整查看；重要警告不能只藏在“更多”。
- 版面置顶主题与普通主题分组，长置顶区可由用户收起并记住选择。
- 原站页码和排序始终可还原，不能用“推荐”取代现有顺序。
- 没有发帖权限时提供原因或原站说明，不显示可点击后才报错的主按钮。

## 9 帖子阅读页面

### 9.1 信息从上到下的顺序

1. 控制栏：返回来源、短标题或当前位置、更多。
2. 主题区：版面、完整标题、必要状态、主题元信息。
3. 内容区：首帖及回复楼层、引用、媒体、评分与投票。
4. 分页区：当前页与总页、上一页、下一页、跳页。
5. 单条底部阅读工具栏：回复、收藏、楼层定位；稍后再看、全文搜索和分享收进清楚的更多菜单。

默认字号下，安全区以外的顶部控制栏约 44，底部工具栏约 52；具体高度随系统与大字适配，不以缩字号维持固定高度。正常阅读不额外常驻开发标签、host 地址和长篇增强说明。

### 9.2 楼层结构

- 作者区位于正文上方：32–36 头像、原用户名、楼主标记或公开身份、时间、楼层号、更多。
- 本地备注在原用户名旁或下方显示；不替换原名。
- 正文下方依次放评分摘要与记录、签名预览、楼层操作；留白区分，不对每一项加完整边框。
- 常用楼层动作保留回复、赞、踩与更多。评分、查看对话、引用、复制、举报和原站权限允许的编辑管理操作由更多面板进入。
- 所有分值按原站定义显示。缺数据不当作零，未展开完整记录不冒充已统计完成。
- 评分记录保留查看完整记录的入口，默认沿用原有展开偏好；信息多时面板展示完整详情，不删除内容。
- 热评、楼主、锁定和已编辑分别用文字与轻标记表示，不大面积染色。
- 签名档默认适度收起，允许展开；不能把签名与正文统计、搜索或屏蔽条件混算。

### 9.3 引用与查看对话

- 引用采用次内容面和 2–3 宽副色边线；显示可识别的原作者、楼层与定位入口。
- 引用正文不小于 15，行高不小于 24；不使用极浅灰字表达整段引用。
- 嵌套每级缩进 12，最多保留两级视觉缩进；更深关系通过层级标签与展开呈现，避免把正文挤成细列。
- 长引用可显示约 6 行摘要并展开；被原站限制或被屏蔽的内容不借“展开”绕过权限。
- “查看对话”进入全屏对话视图，顶部显示当前追溯中心与返回入口。分支顺序、父子关系、多父引用和跨帖边界延续现有含义。
- 对话读取显示实际进度，支持停止、继续和失败重试；关闭后返回原楼层，保留正文选区之外可恢复的阅读上下文和草稿。
- 跨帖下游不伪称已全量搜索；尚未读取、删除和权限不足的楼层分别说明。

### 9.4 分页、定位与阅读位置

- 保留真实页码，不把帖子强制改成难以定位的无限流。
- 底部页码区提供上一页、当前页与总页、下一页；点击页码打开输入面板。
- 楼层定位面板支持输入楼层、回首帖、到末页及原站可用的阅读筛选。
- 从列表首次打开按原站链接意图定位；用户选择“继续阅读”时才恢复本机阅读记录，不擅自覆盖带楼层的链接。
- 翻页先呈现新页框架，数据准备后一次定位；不先跳顶再多次滚动。
- 同页同步、图片加载和评分补齐不得把正在看的文字推离位置；必须为媒体保留合理占位。
- 返回列表恢复具体主题锚点与相对偏移，而不是只恢复近似滚动像素。
- 引用定位失败保留来源上下文，并提供返回，不连续弹出错误窗口。

### 9.5 屏蔽内容

- 主题、楼层及引用屏蔽遵循现有规则与账号范围，不把本地屏蔽扩展为其他账号的全局行为。
- 内容替换为可读摘要：“已按你的规则折叠”，提供查看命中原因与调整规则入口。
- 是否允许临时展开由对应规则与权限确定；临时展开不修改永久规则。
- 隐藏引用只处理匹配的部分，保留回复者正文及不相关引用。
- 标题和发言条件异常应在规则页显示，不以静默漏过滤或整页空白表现。

## 10 图片与其他媒体

### 10.1 图片

- 正文图片最大宽度等于内容宽度，默认保持原始比例，不统一裁切为封面。
- 超长图在正文保留适当预览并显示“查看长图”；完整查看不改变原图。
- 占位使用已知尺寸或稳定比例；加载失败显示重试，不保留无意义的大块空框。
- 隐藏图片保持原权限及显式查看动作，预热不能提前展示。
- 点击图片进入全屏查看器：单击切换控制层、双击缩放、双指缩放、放大后拖动、在未放大时切换前后图片。
- 缩放、返回与左右切换手势不得互相抢占；始终有显式关闭和前后切换的可访问操作。
- 显示当前位置，如“3 / 8”；提供系统分享、保存到照片或文件的合法操作。
- 保存照片仅在用户请求时申请相应权限；拒绝后仍允许继续阅读和使用其他保存方式。
- 正在查看时不因后台列表更新替换当前图片；错误不得导致退出整篇帖子。

### 10.2 视频、音频、附件与特殊内容

- 使用适合手机的播放控件，不自动播放有声视频或音频；滚动出视图不自动开启其他媒体。
- 视频、B 站嵌入或音频无法播放时，保留标题与原链接，给出打开原页面的选择，不伪造播放按钮。
- 附件显示原文件名、已知类型和大小；未知信息不编造。点击前区分下载与打开。
- 下载结束说明“已下载到临时文件”，提供“存储到文件／分享”；系统分享窗口打开不等于文件已永久保存。
- 代码块、表格和公式保留局部横向滚动；代码复制只复制内容，不含行号和装饰。
- 回复可见、折叠、投票后可见等内容维持原站规则；预览和本地索引不能提前暴露。

## 11 发帖与编辑

### 11.1 编辑器总体布局

手机默认使用**单个可持续输入的编辑区**。顶部为取消或返回、任务标题、提交；正文上方按需显示版面、标题、引用对象等；键盘上方是一条编辑工具栏。

UBB 使用“编辑／源码／预览”三个明确模式：默认“编辑”承载可视化输入；源码用于精确编辑；预览用于只读核对。Markdown 使用“编辑／预览”。不默认把可视化与源码上下各压半屏；大屏后续可以提供双区偏好，但不能成为手机操作前提。

- 模式切换必须保留文本、选区或合理的逻辑位置、撤销历史和输入法组合态。
- 不能可靠保真的 UBB 格式必须提示使用源码处理，不能切换一次就静默丢失标签或受限内容。
- 最终提交格式、权限与校验仍由原站契约决定。

### 11.2 键盘与工具栏

- 键盘出现时隐藏根导航及无关阅读工具；只保留编辑任务所需控制。
- 工具栏第一层放表情、图片或文件、格式、引用、收起键盘；宽度不足时合并低频项，不能缩小触控。
- 加粗、链接、颜色、字号、列表、代码、公式、表格、视频与音频放在分类面板中；面板可展开，不把十几个小图标挤进一行。
- 键盘、表情面板和格式面板使用同一底部占位逻辑，切换时不让正文跳到首行。
- 选区必须持续可见，输入时能滚动到插入点；工具栏不得压住中文候选栏。
- 正文自然增长或在明确编辑区域内滚动，避免网页、编辑器、半屏面板出现三层嵌套滚动。
- 工具栏点击不得丢失中文组合输入或触发发帖；必要时等输入法完成当前组词后再切换编辑模式。回车不触发发送，提交必须由明确按钮触发。

### 11.3 上传

- 优先调用系统照片与文件选择器；不在打开编辑器时预先索取整个相册权限。
- 每个已选择文件展示缩略图或类型、名称、真实进度、失败重试和移除操作。
- 上传失败只影响对应文件；用户取消选择不插入空标签，不提交帖子。
- 是否支持多选、格式与大小上限，以当前原站能力为准，面板在选择前说明已知限制。
- 已开始的上传不因切换预览重复执行；尚未结束时提交按钮说明等待原因。
- 回复或编辑无法确认是否已提交时，显示“提交结果尚未确认”，先查看原站结果，不能自动再次发送。

### 11.4 草稿与退出保护

- 草稿按网页账号、任务类型、版面或主题、具体编辑对象隔离；普通主题与投票草稿分开。
- 编辑区显示“已保存到本机”及时间，只有实际写入成功才显示；保存失败保持醒目的重试入口。
- 选择图片与文件后，区分已上传资源和仅本次会话可用的待上传文件，不承诺重启后自动恢复系统文件权限。
- 检测到旧草稿时给出时间、任务对象与“恢复／暂不恢复”；恢复前不覆盖当前输入。
- 离开时有未提交内容，选择为“保存草稿并退出”“继续编辑”“丢弃修改”。自动草稿保存不等于原站保存。
- 内容确认提交成功后再清除对应草稿；网络超时、返回未知、应用退后台不触发清除。
- iOS 退后台后的持续保存与上传不作保证；必须在正常编辑阶段及时保存，并在回来时核对实际状态。

### 11.5 UBB 扩展、互转与投票

- 保留引用、分割线、代码块、内嵌 Markdown、数学公式、原样文本、命名字体、折叠图片，以及 1–6 行列插入表格的功能目标。
- 表格编辑使用独立的大面板或全屏，不在窄工具条中完成网格配置。
- UBB 与 Markdown 互转先显示可检查的结果及不等价项，由用户明确替换；回复可见等权限内容禁止无提示替换。
- “手动同步”“旧预览”等修复入口归入编辑器更多菜单，不占普通输入首屏。
- 投票表单保留原生 2–20 项、有效天数、最多可投数量和投票后结果可见规则；限制提示贴近字段，最终原站校验不可省略。
- 普通回复小尾巴沿用用户设置；匿名回复及心灵之约自动停用，不为手机新增自动署名。
- 签名档复用适合手机的 UBB 模式，但保留不提供表情选择器的既有约束。

## 12 搜索与批量读取

### 12.1 全站与版内搜索

- 搜索入口位于浏览与版面顶部；打开后显示输入框、搜索范围和当前账号的历史。
- 范围包括原站支持的主题、用户、版面、版内与全站；范围不能只用难认的图标。
- 搜索历史明确是本机数据，可单条删除或全部清空；切换账号不混用。
- 本地输入联想不得伪装成外部 AI 结果，也不发送到外部 AI 服务。
- 结果保留原顺序、时间、浏览量等原有排序；排序依据与当前范围可见。
- 条件变更保留关键词；无结果可修改范围，不显示虚构推荐。
- 按需挂载列表提供“显示全部／恢复按需显示”，保留原有页内查找的可用路径。

### 12.2 帖内全文搜索

- 从帖子更多菜单进入独立全屏任务，显示搜索条件、读取范围、进度和命中结果。
- 保留关键词、作者用户名或 UID、表情编号、是否包含引用等既有能力；匿名只匹配公开身份。
- 开始读取或刷新前说明需要逐页读取及可能改变原站足迹或已读状态，由用户确认。
- 默认仅手动触发；不得在打开帖子时悄悄搜索全帖。
- 未缓存页面按既有至少一秒的间隔串行读取，与查看对话共用已有缓存和队列，不为手机加速取消限速。
- 提供暂停、继续、失败重试与刷新；结果标注已读范围，不把部分命中描述成全帖最终结果。
- 关闭搜索视图不等于删除进度；离开当前主题时暂停。应用进入后台后的持续运行不承诺。
- 点击命中进入对应楼层，返回后仍保留关键词、结果与读取状态。

## 13 消息与个人内容

### 13.1 消息中心

- 一级显示站内消息分类与未读信息，按原站提供的类别组织，不把通知、回复和私信混成一条没有来源的时间线。
- 分类较多或大字状态下使用可滚动分类条或纵向分类入口，不缩小文字。
- 未读徽标只在有可信计数时显示；不能取得总数时不伪造“0”。
- 不默认在锁屏、截图预览或根导航上暴露私信正文。系统推送未接入时，只说明应用内刷新，不提供虚假的推送开关。

### 13.2 私信会话

- 联系人列表显示头像、原用户名、可用的最后消息摘要、时间和未读状态。
- 本机置顶显示图钉和明确状态，保留原有“新置顶排前”的含义。未加载近期记录的置顶联系人仍保留打开入口。
- 会话全屏展示，气泡宽度原则上不超过内容宽度约 82%；长文本可正常折行、选择和复制。
- 不凭客户端猜测“已送达”“已读”或“对方正在输入”；只显示原站真实提供的状态。
- 连续消息按时间与发送者适度分组；原始发送时间和失败状态仍可查看。
- 键盘打开后最后一条消息可见；加载旧消息不把当前阅读点推走。
- 发送失败保留输入和原消息；结果不确定时不自动重发。联系人或账号切换不能串用草稿。
- 原站暂不能适配的会话操作使用保留上下文的原站窗口，不在增强气泡中伪造成功。

### 13.3 我的

“我的”顶部只显示当前网页账号、头像和清楚的账号状态；OpenID 绑定作为独立状态行，不用重复的大号欢迎卡。

常用入口顺序为：收藏、稍后再看、草稿、浏览记录、我的主题与回复、关注与个人资料。设置与帮助位于下方，不把所有入口做成五颜六色九宫格。

- 收藏保留原站分组；稍后再看明确是本机功能，不能合并名称。
- 稍后再看独立页面提供搜索、分页、已读、删除、导入、导出与清除已读。加入和移除可撤销，清空批量内容需确认。
- 关注与用户主页保留备注编辑，最多 80 字，显示原用户名和仅自己可见的说明。
- 用户主页进入全屏资料任务，提供原站允许的关注、私信和内容入口；不在手机要求悬停才能操作。
- 浏览记录按实际来源与原站行为呈现；本机“继续阅读”记录若新增，应单独命名与管理。

### 13.4 收藏分享与配置导入

- 分享收藏夹选择分组后显示导出范围与条数；沿用每次最多 2000 条，字符串只包含分组名、帖子编号和标题。
- 导入先预览内容和目标分组，说明已有收藏保持原分组；支持停止、继续和失败重试，不用模糊的一键覆盖。
- 批量进度显示已处理、成功、失败和剩余；关闭面板不默认取消任务，但后台持续执行不承诺，必须有可恢复状态。
- 个人设置备份与稍后再看导出是两个独立操作；不能让用户以为一份 JSON 已包含全部个人数据。

## 14 登录与 OpenID 绑定

### 14.1 四个基本状态

| 状态 | 界面表达 | 主要动作 |
| --- | --- | --- |
| 网页未登录 | “先登录 CC98” | 打开真实官方登录页面 |
| 网页已登录，未绑定 | “Reborn 尚未绑定当前账号” | 绑定同一账号；可切回原站 |
| 网页已登录，绑定一致 | “已绑定当前账号” | 正常使用；设置中可重新验证或本机解绑 |
| 网页与绑定不一致 | “当前网页账号与绑定账号不同” | 重新绑定当前账号；不复用旧摘要放行 |

不能用网络失败、加载中或读不到网页账号，直接宣告“未登录”或“账号不一致”。这些情况使用“暂时无法确认账号”并允许重试。

### 14.2 登录与绑定的呈现

- 官方登录保留真实域名与系统容器边界，不仿造密码输入页。
- 绑定前说明将验证同账号并读取绑定所需身份信息，不让用户以为是在注册新账号。
- 使用系统授权窗口；当前论坛页面与系统窗口可能登录不同账号，界面必须解释错账号恢复方法。
- 当前 Reborn 要求绑定时，显示一处清晰的绑定引导；不要同时出现原生长横幅、网页遮罩和诊断提示三层重复说明。
- 不弱化现有同账号与水印门槛。用户取消或拒绝后仍可明确切回原站，不使用无限重开授权窗口的方式施压。
- 授权过程中只保留一个进行中的请求，显示取消。重复点击不生成多套授权流程。
- 成功后更新当前页面状态，不自动重载，不清草稿，不用成功弹窗挡住正在阅读的内容。
- 账号不一致时显示“请使用当前论坛账号重新授权”；再次操作应支持重新登录选择，不能陷在同一个错误 SSO 账号中。

### 14.3 退出与清理严格分开

在账号与数据设置中，分开呈现以下操作及影响：

1. **退出论坛账号**：执行原站退出；不等于清理所有本地内容。
2. **解除本机 OpenID 绑定**：移除绑定摘要，不退出论坛，不表示撤销站方授权。
3. **清除站点数据**：可能移除登录、网页本地数据与未备份内容，属于高风险维护操作。
4. **恢复个人设置默认值**：只按已说明范围恢复设置，不默默清空草稿和稍后再看。

任何诊断、错误或复制操作均不得显示 Cookie、token、授权码、完整回调参数或帖子私信正文。

## 15 设置与原站模式

### 15.1 设置分组

采用“我的 → 设置”的完整页面，不再沿用桌面小 popup 的固定宽高。建议分为：

- **外观**：明暗、自动时段、六组配色、自定义、界面风格、圆角。
- **阅读**：正文大小、行距、表情大小、标题密度、媒体加载与预热、阅读位置。
- **浏览与交互**：链接打开方式、手机全屏阅读、列表按需显示、版面置顶。
- **编辑**：默认编辑模式、回复小尾巴、草稿入口与相关说明。
- **屏蔽与备注**：版面、标题、UID、发言条件、本地备注管理。
- **账号与绑定**：网页账号状态、OpenID、退出与本机解绑。
- **数据管理**：个人设置备份与导入、稍后再看导出、批量清理及影响说明。
- **帮助与兼容**：原站模式、状态与诊断、版本、项目与隐私、手动获取新版。
- **实验功能**：只显示当前真正接入的实验项及明确说明。

设置搜索作为后续可选能力，不以搜索代替合理分组。设置变更即时生效并说明是否仅本机；不会因保存某个开关重载整页表单。

### 15.2 桌面偏好迁移

- 桌面左侧效率栏在手机不显示，常用入口由四个主导航与“我的”承接；不删除备份中的原设置。
- “帖子侧拉窗”在手机呈现为全屏阅读行为的说明，不能把启用值直接映射成未支持的 iframe。
- “链接在新页面打开”在手机指向清楚的任务窗口与外链策略；不创建没有标签管理入口的一堆隐藏窗口。
- 悬浮展开改为点击查看或更多菜单；不得要求悬停。
- 图片预热沿用默认关闭及用户选择，优先考虑手机流量、内存和权限；不为了动画流畅扩大请求范围。
- 按包内版本更新 App，不在 iOS 设置中沿用“下载扩展 ZIP 即已升级”的含义；手动获取新 IPA 不承诺后台自动安装或续签。

### 15.3 屏蔽规则编辑

规则页面分为版面、标题、用户、发言条件四个可识别入口，避免把所有表达式和说明同时堆在一个长表单。

- 版面规则提供版面查找与已选列表；展示名称和必要编号，移除有明确操作。
- 标题规则区分普通关键词和 `/正则/i`；输入时校验，语法错误贴近输入框，不允许保存看似有效的无效规则。
- 用户规则明确匹配 UID 或已支持的身份条件，不把本地备注当成原用户名匹配；添加前显示能可靠取得的目标信息。
- 发言条件默认使用引导表单：正文文本或表情、出现次数、比较方式与数值、且或关系；高级模式保留 AND、OR、NOT、括号和正则。
- 表情选择复用现有六组表情面板，点击填入标准编号，并保留手动输入路径，不只保存图片外观。
- 数值条件保留本楼风评、赞数、踩数、赞踩比和赞踩总数。风评来自完整评分记录的净变化，不等同于赞减踩；赞踩比为赞除以踩，有赞无踩为无限大，零赞零踩或缺失信息不判定。
- 正文条件不含引用与签名；多条规则任一命中即折叠。规则预览必须按相同含义解释，不能为简化 UI 改成另一种判断。
- 高级表达式较长时使用可换行的大输入区，附错误位置和示例；不在一行横向滑动的狭窄输入框中编辑。
- 每条规则有清楚的内容摘要和编辑、删除入口；批量移除需确认。命中或正则超时等异常可在规则页定位，不静默吞掉。
- 规则计算沿用本地与独立线程限时约束，不为了提供预览把帖子正文传给外部服务。

### 15.4 备份与清理

- 导入前显示配置类别、数量、账号适用范围和覆盖规则，再由用户确认。
- 个人设置备份沿用现有范围：主题、阅读显示、屏蔽规则、用户备注、私信置顶和版面置顶；不含登录凭证、API 密钥、草稿及稍后再看。
- 备注、私信置顶等仍按原账号恢复，不能为导入方便改挂到当前账号。
- 清站点数据页面列出可能损失的内容与可用备份入口；默认操作是取消，不提供一触即清的图标。
- 不将“清 Cookie”作为任何网络错误的第一推荐动作。

### 15.5 原站恢复

- 每个增强任务的更多菜单可到达“切回原站”，不超过两步。
- 增强失败时把“切回原站”直接放在错误区；不让用户先完成增强授权才能恢复。
- 切换前提示可能重载；如存在未提交输入，先执行草稿保护，不假定已经保存。
- 尽量保留当前官方地址、网站登录和可恢复的阅读位置，不强制回首页。
- 原站模式使用一套紧凑浏览控制：真实来源、后退、重新加载或停止、分享、恢复 Reborn。它是明确的兼容模式，不再同时叠加四个业务主导航和网页自己的导航。
- 进入原站模式后不把未适配网页强行套上统一字体或重排表单；用户应能辨认这是原站。
- 不支持增强的网页窗口保留原站控件与“返回论坛”，不能假装已经拥有主页面的绑定与桥能力。

## 16 状态与错误文案

### 16.1 必备状态

每个页面或异步组件至少定义：初始、加载、成功、空、局部失败、整页失败、权限不足。表单另定义校验失败、提交中、提交成功、结果未知；批量任务另定义暂停、取消和部分完成。

| 场景 | 首要表达 | 恢复动作与保护 |
| --- | --- | --- |
| 首次加载 | 稳定导航及对应列表或楼层骨架 | 可停止或返回，不展示虚假帖子 |
| 当前网络无法访问 | “暂时无法连接 CC98，请确认校网或 VPN 可用” | 重试；保留已有内容与输入，不擅自宣告 VPN 断开 |
| 超时 | “连接超时”并说明具体任务 | 重试读取；提交结果未知时先核对 |
| 登录过期 | 原站可确认后显示“需要重新登录” | 保留草稿，进入官方登录 |
| 无权限 | “当前账号无法查看此内容”及原站可用说明 | 返回来源；不反复自动重试 |
| 已删除或不存在 | 原站提供的准确状态 | 返回来源或查看其他楼层 |
| 列表没有内容 | 说明当前分类或筛选范围 | 修改筛选、刷新或正常返回 |
| 本地列表为空 | “还没有稍后再看的主题”等具体表达 | 告知加入方式，不放无关插画卡 |
| 局部媒体失败 | 原位置显示媒体加载失败 | 单项重试或打开原链接 |
| 增强接管失败 | “此页面暂未完成增强” | 重试增强或切回原站 |
| 授权取消 | “已取消，尚未完成绑定” | 用户主动重试或切回原站 |
| 授权账号不一致 | “授权账号与当前论坛账号不同” | 重新登录授权，不写入成功状态 |
| 草稿保存失败 | “尚未保存到本机” | 重试保存，并可手动复制内容 |
| 上传部分失败 | 对应文件的错误与真实进度 | 单项重试或移除，正文不丢 |
| 提交结果未知 | “提交结果尚未确认，请先检查原帖” | 核对结果，不自动重发 |
| 当前版本未接入 | 具体能力说明 | 有真实原站路径则提供，否则解释，不假成功 |

### 16.2 文案统一

- 用“论坛登录”“OpenID 绑定”“解除本机绑定”“切回原站”分别表达真实动作。
- 用“保存草稿”“加入稍后再看”“收藏到分组”区分三个操作。
- “同步页面”指重新读取已加载原页面；“重新加载网页”指实际导航刷新，不能共用一个含义不清的圆箭头。
- 错误先说发生什么，再说用户现在能做什么；不把堆栈、接口路径或技术术语作为主要说明。
- 删除单条明确对象；清空批量内容明确范围和影响。
- 不用“网络异常，请稍后再试”覆盖登录、权限、证书和提交未知等不同情况。

## 17 动效、触觉与性能体验

以下时长为项目交互目标，不是已测得的性能数据。

- 按压态应在约 100 毫秒内出现；业务结果仍以真实响应更新。
- 普通面板和页面转换以约 180–280 毫秒为基准，优先使用系统过渡。
- 使用减少动态效果设置时，去除大幅平移、弹跳、视差和骨架闪动，采用短淡入或直接呈现。
- 不对每次楼层加载进行逐卡片飞入；不以动画掩饰重复重建和内容跳动。
- 图片占位、文本骨架和容器高度应减少阅读布局位移；不让整个页面反复闪白或闪黑。
- 触觉只辅助明确选择、成功或风险操作；赞踩、滚动和普通翻页不连续振动，系统禁用时尊重设置。
- 大帖、长对话和大量表情允许按需挂载，但必须保持定位、选择、搜索与无障碍语义；已有“显示全部”路径保留。
- 视图关闭后释放不再使用的媒体和窗口；不能为恢复列表保留无限多个网页任务。
- 加载变慢时给出可理解状态与取消入口，不以假的进度或持续旋转代替恢复路径。

## 18 无障碍与隐私

### 18.1 无障碍验收底线

- 所有主要流程支持 VoiceOver：导航、读帖、楼层操作、搜索、编辑、上传、授权状态和原站恢复。
- 每个图标按钮有明确名称，状态有“已收藏／未收藏”等值；计数不代替操作名称。
- 楼层作者、时间、正文和操作的朗读顺序与视觉顺序一致；装饰分隔、背景水印和重复图标不制造朗读噪声。
- 面板打开后焦点进入面板，关闭后回到触发控件；错误与成功通知不反复抢走正在输入的焦点。
- 仅靠拖动、滑动、长按和颜色才能完成的动作必须有显式替代入口。
- 支持系统加粗文字、提高对比度、减少透明度、减少动态效果与大字；内容区不能因主题或材质变得不可读。
- 普通正文可选中、复制，网页缩放不被全局禁止；图片查看器和系统手势不互相封锁。
- 键盘与外接键盘焦点清楚，表单标签和错误可被辅助技术识别。

### 18.2 隐私呈现

- 只在动作需要时索取照片等权限；权限拒绝不阻止其他无关功能。
- 剪贴板导入仅由用户点击触发，不启动即读取收藏分享字符串或配置。
- 分享帖子时默认分享原站链接；导出本地数据前显示包含范围，不附带登录和绑定凭据。
- 用户备注、草稿、稍后再看和置顶信息在对应页面清楚标示本机属性；不暗示已云同步。
- 诊断按已有脱敏边界展示，不把“发送完整日志”作为排错前提。导出诊断只能包含允许的状态和错误码。
- 私信与受限内容不为“好看的最近内容卡片”出现在无关根页面上。
- 账号切换或本地数据恢复时，必须先验证当前账号范围，再显示私有信息。

## 20 关键流程与设计验收

### 20.1 必须画全的核心流程

后续高保真设计不能只交首页。每条流程至少覆盖正常、等待、失败与返回状态。

1. 启动 → 原站登录 → Reborn 未绑定 → 系统授权 → 成功 → 取消或错账号重试。
2. 十大或新帖 → 主题 → 翻页 → 引用定位 → 查看对话 → 返回原列表位置。
3. 版面 → 发主题或投票 → 输入 → 上传取消及失败 → 预览 → 提交成功或结果未知。
4. 帖子 → 回复或引用 → 退后台 → 返回编辑 → 保存草稿并退出 → 恢复草稿。
5. 消息 → 私信联系人 → 历史消息 → 编辑发送 → 失败恢复 → 返回联系人列表。
6. 搜索 → 更换范围与排序 → 主题 → 返回结果；帖内搜索另覆盖暂停、继续和命中定位。
7. 收藏或稍后再看 → 分组管理 → 分享导出 → 导入预览 → 批量部分失败与重试。
8. 外观设置 → 切换明暗与配色 → 大字 → 返回正在读的楼层，输入与位置保持。
9. 增强异常 → 切回原站 → 当前内容可用 → 恢复 Reborn；存在草稿时先保护。

### 20.2 必交页面与状态

| 页面组 | 必交设计内容 |
| --- | --- |
| 启动与账号 | 加载、网络错误、官方登录边界、未绑定、绑定中、错账号、成功与本机解绑 |
| 浏览 | 十大、新帖、关注、精选、空列表、加载更多失败、大字 |
| 版面 | 目录、搜索、置顶、版面详情、公告展开、权限不足 |
| 读帖 | 长标题、首帖、普通楼层、匿名、引用、评分、签名、锁帖、分页与更多 |
| 阅读扩展 | 对话、帖内搜索、图片查看器、隐藏图片、附件下载及失败 |
| 编辑 | 主题、回复、编辑、UBB 三模式、Markdown、工具面板、上传、草稿、投票与结果未知 |
| 消息 | 分类列表、私信联系人、置顶、会话、键盘状态、发送失败与旧消息加载 |
| 我的与整理 | 用户资料、备注、关注、收藏、稍后再看、草稿、历史、分享导入 |
| 设置与兼容 | 外观、阅读、屏蔽、账号、备份导入、数据清理、诊断、原站模式 |

### 20.3 排版与交互验收清单

- [ ] 320、375、402、430 宽度下，主体没有横向溢出，长标题和名字不压住操作。
- [ ] 默认及 200% 大字下，主要文字完整可读，表单标签、错误和确认按钮不被截断。
- [ ] 深浅色下正文、辅助说明、按钮与评分符合各自对比要求。
- [ ] 一屏没有重复顶栏、双重底栏或三层增强说明。
- [ ] 每个主要触控目标满足项目尺寸；不依赖悬停、长按或不可发现手势。
- [ ] 正文、引用、表格、代码、公式、超长图片和大量表情可正常阅读。
- [ ] 下拉刷新、列表滚动、图片缩放、返回与编辑选区没有明显手势冲突。
- [ ] 标题、媒体和异步信息加载后，不把当前阅读段落多次推走。
- [ ] 进入主题、对话、搜索及外链后，返回能恢复正确来源位置与筛选。
- [ ] 原站登录、OpenID 和网络未确认状态彼此区分，取消后有正常退出路径。
- [ ] 账号变更不会显示或提交另一个账号的私信、草稿和本地数据。
- [ ] 中文输入、表情选择、工具面板、预览和源码切换不丢字、不重复提交。
- [ ] 所有上传、发送与批量任务有真实进度或阶段，失败可恢复，结果未知不自动重发。
- [ ] 临时下载、永久保存、分享成功与打开系统面板不被混称为同一完成状态。
- [ ] 所有权限不足和未接入能力有准确说明，不存在可点击的虚假成功入口。
- [ ] 原站恢复随时可达，可能影响草稿的动作先明确保护。
- [ ] VoiceOver 可完成主要流程；减少动态效果、大字与提高对比设置有效。

以上项目必须在相应设计稿和实际手机界面中检查。设计稿通过不替代后续真机交互验证；原站权限与网页行为变化也不能只靠静态截图验收。

## 21 后续执行顺序与变更规则

### 21.1 从核心阅读向完整功能推进

先完成导航、主题与楼层组件、编辑框架和状态体系，再按以下顺序展开页面。分阶段用于控制相互依赖，完整功能目标继续保留在第 19 节清单中。

1. **首批设计**：浏览、版面、读帖、分页、登录绑定、原站恢复，以及对应深浅色和大字。
2. **输入与消息设计**：回复、发主题、上传、草稿、投票、私信和消息。
3. **完整增强设计**：对话、全文搜索、收藏分享、稍后再看、规则、备注、设置与数据管理。
4. **实验与特殊页面**：BBS 风格、少见原站权限页；问号等功能在依赖和授权齐备后独立设计。

### 21.2 规范变更必须连带更新什么

- 新增功能必须给出入口、所属容器、权限条件、空与错误状态、返回行为，以及草稿或账号影响。
- 调整字号或色彩必须检查正文、引用、表单、深色与大字，不只改首页。
- 调整底栏必须检查键盘、图片查看、私信和读帖，不能新增第二排常驻控制。
- 移动或合并设置必须保留原数据含义和迁移路径；不能借 UI 改名偷偷改变“自动主题”“同步”“备份”的原有语义。
- 延后功能保留在完整性清单中，标明当前替代路径或未开放；不得直接从设计目标中删除。
- 规范变更由产品方向统一决定后更新本文件，页面级临时实现不能反向定义新的全局规范。
