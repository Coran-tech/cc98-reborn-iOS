# iOS 验证壳的 OpenID 接入条件

本轮保留原站网页登录，独立 Reborn OpenID 授权尚未接入。**网页登录成功不等于 Reborn 已绑定。** 验证壳不得伪造 UID、水印或绑定状态来放行增强界面。

## 哪些功能可以先验证

| 功能 | 本轮处理 |
| --- | --- |
| 官方网页登录、原站编辑和上传 | 由 WKWebView 中的原站执行，不需要先申请另一套论坛登录客户端 |
| 包内 Reborn 脚本、样式和资源加载 | 可以验证注入和资源加载；已登录账号仍受现有绑定遮罩约束 |
| 登录后的完整 Reborn 编辑和阅读 | 待下列可信绑定流程接入后验收，不能用原站模式通过代替 |
| 问号授权与服务会话 | 不属于本轮接入；另需问号维护者批准，不能复用网页登录状态冒充 |

## 请 CC98 OpenID 维护方确认

1. **客户端用途**：批准独立 iOS 公开客户端，或明确允许既有扩展客户端增加原生 App 用途。App 内不保存客户端私密密钥。
2. **授权流程**：支持 authorization code、PKCE S256，以及准确注册的回调 URI。Chrome 扩展回调不能原样充当 iOS 回调。
3. **权限范围**：确认本地身份绑定所需的 scope 和官方 `/me` 访问权限，不申请与验证壳无关的论坛权限。
4. **身份字段**：`/me` 必须提供可与网页当前账号匹配的 CC98 UID，以及既有水印要求所需的 `watermarkId`。分别验证 UID、绑定成功和实际水印，不能只看 `bound: true`。
5. **回调选择**：首选站方允许的 App 专属 URL scheme；若必须采用 HTTPS Universal Link，再确认域名归属、关联文件和签名能力。免费重签可能改变 Bundle ID 或 entitlements，须按实际安装包复核。
6. **嵌入与分发范围**：确认在独立 App 中直接加载原站并使用本地 Reborn 增强的许可范围，区分个人测试和向其他人分发。

账号密码、论坛 access/refresh token、VPN 凭据不属于需要交付给项目维护者的配置资料。配置只应包含获准的公开 client ID、端点、scope、回调 URI 和字段契约。

## 获准后的实现和验收

- 通过 `ASWebAuthenticationSession` 发起授权；随机 `state` 和 PKCE verifier 只在当前短期流程内有效。
- 用本次授权的临时 access token 调用官方 `/me`，与 WKWebView 当前账号 UID 比对。系统授权会话和网页可能是不同账号，必须明确拒绝不匹配结果。
- 仅保存原有本地身份与水印摘要，丢弃临时 token；网页论坛凭据始终留在官方 Origin 的网站数据仓库中。
- 取消、错误、过期、错误 state、重复回调、授权中途换号都不能产生绑定；原站模式仍可恢复。
- 覆盖一次正常绑定、错账号拒绝、退出/换号清理、实际水印显示以及重签后回调五条真机路径。

## 后续启用问号还需要

问号维护者另行确认新客户端 audience/azp、nonce ID Token、跨客户端 `sub` 与历史记录的连续性。现有会话有效期为 15 分钟；未经协议变更，不假设 iOS 能静默续期。问号必须单独同意，不能因绑定水印就自动向问号服务发送 ID Token。
